# 财务本金复利：私人事实台账 v2

> 状态：首版产品与工程基线
> 更新：2026-09-16

## 1. 产品边界

该功能位于「复利系统 → 财务本金复利 → 某一资金计划」，只回答四个问题：用户投入了多少、排除资金进出后实际赚亏多少、当前持有什么、执行是否偏离用户自己当时制定的规则。

它不是证券投资顾问、行情或交易系统。系统不连接银行和券商，不推荐或比较具体产品、仓位、配置与买卖时点，不预测或承诺收益。PE、宏观和资金流等内容只能作为用户自己的判断笔记保存，不能成为系统背书的交易结论。

财务计划不使用通用复利项的「复利已出现／目前线性」、投入次数、每周行动和 12 周分红判断。12 周仅用于判断这套记录机制是否可运行；日常采用按月核对、按季度回看。

## 2. 页面与口径

详情页固定为「概览｜记录｜持有｜计划」四个页签，不增加底部导航。

- 概览：直接汇总当前持有中的累计投入、当前余额和实际涨跌，并补充计划总额快照形成的期间损益、XIRR 条件和执行偏差。
- 记录：资金事件、计划总资产快照、待核对项、判断笔记及更正历史。
- 持有：先展示当前持仓的投入本金、现在余额与涨跌，再允许在「总览／按渠道／按标的」三种口径之间切换；同时保留份额类别、投资方向、分类来源和用户自设上限。
- 计划：把计划期限、执行规则、当前实际进度和用户自设的长期测算情景放在同一页，再提供收益去向、导出与删除。

首次创建不是先产生一个空账本。用户通过四步完成一版可执行计划：目的与 1—60 年期限、投入方式与周期、用户自己选择的标的或方向、记录起点和核对频率。年化收益率测算假设为可选且不预填；若用户填写，确认页明确标记它只是用户假设，不是系统预测、建议或收益承诺。

“计划标的”只描述用户准备跟踪什么，不等于已经买入或持有；真实持有必须在持有页用独立日期和金额确认。系统不提供候选产品、默认仓位、收益率或标的评价。首次保存会在同一财务设置事务中建立 profile 与规则 v1，避免出现只有台账、没有投入计划的状态。

持仓汇总采用「渠道 + 产品 + 份额类别 + 投资方向」作为同一持仓键，每个键只取最新一条已确认快照。旧快照保留用于审计，但不会与新快照重复相加。投入本金缺失时，系统仍可展示余额和结构占比，但该持仓及其上级汇总的涨跌必须显示为「暂不能计算」，不能把未知成本当作 0。按渠道和按标的都复用同一批最新持仓，因此三种视图必须可以逐项对账。

资金变动与持有快照仍是两类事实：前者回答「何时投入或取出」，后者回答「目前持有什么、值多少」。产品和渠道完全匹配的最近资金变动会展示在对应持有项下，帮助用户确认例如一笔新投入已经被纳入成本；系统不会把资金变动再次自动加到余额中，避免重复计算或把买入金额误当成实时市值。

计划总资产快照按当日结束时理解；同日资金事件已包含在快照内。账户总额、下属产品明细和买卖金额不会再次与快照相加。持有明细只解释结构，不进入计划总资产核算。

金额用整数分存储和计算，前端保持字符串展示，不通过浮点数重算。多币种分别呈现；没有逐日汇率及来源时不强行折算。

## 3. 确定性计算

只有 `CONFIRMED` 记录进入核算。`DRAFT`、`UNCERTAIN`、已修订和已作废内容不进入需要明确口径的统计。

```text
跟踪期净投入 = 外部投入 + 期间纳入的存量资产 - 外部取出
投资损益 = 期末资产 - 期初资产 - 外部流入 + 外部取出 - 计划外另付费用/税费
```

内部转移、计划内买卖、分红、利息和收益再投入不重复增加外部本金。期初日资金事件不再次计入，因为期初快照已包含当日结束状态。

只有两个不同日期的已确认总资产快照、完整外部现金流且求解唯一时才展示 XIRR。不满一年标明为短期折算；数据缺失、结果不收敛或可能多解时显示「暂不能计算」。

规则采用追加版本，不覆盖旧规则。系统只机械呈现投入金额或用户自设上限的偏差；跨越多个规则版本时不使用最新版本改写历史，而要求分段核对。

固定金额计划可以生成一个确定性的长期测算情景：当前余额按用户填写的年化收益率复利，后续每期投入按期末投入计算。计划目标日锚定在计划开始日，不能每次打开页面就把完整期限向后滚动。页面必须同时展示当前余额、未来计划投入、测算增长和期限结束时的测算金额，并明确将实际结果与假设结果分开。非固定金额计划、币种不一致、条件缺失或数值超界时不伪造单一结果。

```text
期末测算金额 = 当前余额 × (1 + 期收益率)^剩余期数
              + 每期投入 × [((1 + 期收益率)^剩余期数 - 1) / 期收益率]
```

年化假设为 0 时，第二项退化为「每期投入 × 剩余期数」。所有测算都只是按用户参数计算的数学情景。

## 4. 数据对象

迁移 `server/sql/038_financial_ledger.sql` 新增：

- `financial_plan_profiles`：计划范围、起点方式、币种、期限、周转金状态和授权状态；
- `financial_records`：外部投入/取出、内部转移、买卖、收益、费用、存量纳入和待确认金额；
- `financial_snapshots`：明确日期及覆盖范围的计划总资产快照；
- `financial_holdings` / `financial_aliases`：持有明细和用户确认的别名归类；
- `financial_rule_versions`：决定日、生效日、投入预算和用户约束；
- `financial_decision_notes`：用户当时的判断、决定与依据；
- `financial_reviews`：月度或季度核对快照；
- `financial_import_drafts`：AI 产生、尚待用户逐项确认的导入草稿。

所有对象使用 `(thread_id, user_id)` 复合外键绑定当前用户的计划。金额、持有名称、规则、笔记和 AI 草稿放在 AES-256-GCM 加密字段内；部署必须配置独立的 `FINANCIAL_DATA_ENCRYPTION_KEY`。

旧版次数和通用进展继续保留，但不会迁移或折算成金额、投入、收益和财务结论。

## 5. 权限、AI 与数据权利

- 财务台账只接受登录会话，不接受 Shroom API Token；服务端不接受客户端 `userId`。
- 财务信息始终私密，不进入发现、公开菇卡、用户比较或跨用户摘要。
- 首次建立台账需要单独确认敏感财务数据处理说明。
- 普通记录、计算、规则核对和回看不调用 AI。
- AI 导入默认关闭。只有后台明确开启、页面展示实际处理方且用户单独授权后，才可将去除账户凭证的文本发送给模型；授权可撤回。
- AI 只生成候选事实和歧义，意向不能入账；用户选中确认后才写入，来源不明项保持待核对。
- 同一来源文本和每条确认动作都有稳定去重键，重试不重复入账。
- 用户可以导出包含完整修订轨迹的数据，也可以删除该计划下的财务设置、记录、草稿与摘要。

这些是产品和工程控制，不等同于法律意见、资质认定或发布审批。公开发布前仍需以实际服务主体、隐私政策、第三方处理条款和运营方式进行专项复核。

## 6. 首版验收

1. 期初 100,000，期间外部投入 10,000，期末 105,000，投资损益必须为 -5,000。
2. 内部转移、买入和收益再投入不增加净投入。
3. 中途纳入 20,000 存量资产按外部流入处理，不伪装成收益。
4. 只有一个快照时不显示 0 收益，而是「暂不能计算」。
5. 人民币与美元在没有汇率时分开显示。
6. 同产品跨渠道可合并查看，渠道和份额类别仍保留；没有投资方向时显示「待分类」。
7. 更正保留原版本和修改依据；重复请求、重复导入不重复入账。
8. 其他用户及 API Token 不能读取、修改或导出私人财务内容。
9. 当前持有必须成为概览和计划页「实际现在」的同一数据源，不要求额外建立总额快照才显示。
10. 与渠道、产品完全匹配的新投入在持有页可追溯展示，但不会再次叠加到当前余额。
11. 20 年计划在运行 10 年后只计算剩余 10 年，不得变成新的 20 年滚动预测。
12. 页面操作打开的表单必须自动滚动到真实表单位置，不能用固定像素造成「点击没反应」。

## 7. 从零使用路径

新人只需要理解四件事：

1. **计划**说明准备坚持多久、多久投入一次、每次多少，以及跟踪什么；它不是交易指令。
2. **记录**保存真实发生的投入、取出和某天总金额，用于还原期间变化。
3. **持有**保存各渠道、各产品最新余额与累计投入，用于回答现在到底持有什么。
4. **概览**只汇总前述已确认事实，回答总投入、当前余额、实际涨跌和本期是否偏离自己的规则。

空账户从四步计划向导开始；创建后可以先只做计划，也可以按需要选择简单总额跟踪或详细持有跟踪。按钮打开的编辑区必须可见，保存成功后回到原页签并使用同一份服务端数据刷新。所有统计均可从明细逐项对账，未知成本、未确认记录和混合日期必须显式提示。
