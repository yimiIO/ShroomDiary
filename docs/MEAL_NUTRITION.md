# 拍照饮食记录与个体营养参考

已决定（2026-10-04）：保留真实餐食、减少填写；记录 → AI 候选识别 → 确认实际份量 → 已记录摄入 → 完整日对比。一次拍照只需保存和确认份量；菜名、标签、商户、开销都不再必填。照片识别会保存并复用，只有显式重新估算才再调用。普通查看、份量调整和身体资料修改不调用 AI。

## 临床营养评估思路转成产品行为

1. 先确认目的、身体情况及适用范围，再估计需求。不以统一 2000 千卡套用所有人。
2. 数据优先级为用户称重/标签/实际份量说明 > 视觉估算。当前仅支持视觉与文本估算，不能宣称已接入权威食物成分数据库或检测设备。油、糖、酱汁与共享食物存在不可见误差；输出区间，无法判断时保留 null。
3. 获取年龄、生理性别、身高、体重、自报活动量、目标和特殊饮食安排；按本人登录账户持久保存，客户端不选择 userId，旧 API token 不获得新增健康资料权限。填写同意后保存，提供删除。资料不送往识图服务。
4. 健康 18–64 岁、BMI 18.5–30 的成人采用 Mifflin–St Jeor 静息能量 × 自报活动系数（产品近似 1.4/1.6/1.8），展示 ±10% 起始范围。该范围不代表统计置信区间，需结合数周体重、饥饿、训练、实际摄入及专业评估校准。
5. 减脂只对 BMI≥24 且无特殊情况采用温和 10% 起始差额；正常体重不自动减少。增肌不自动提高总热量，规律训练人群蛋白质可用 ISSN 1.4–2.0 g/kg/d 参考。普通成人蛋白质范围低值参考 EFSA 0.83 g/kg/d，高值 1.2 为产品展示参考，并非统一临床处方。
6. 未成年人、≥65 岁、孕哺、肾病、糖尿病/降糖药、进食障碍、其他治疗饮食、情况不明、体重偏低或 BMI≥30，均不套用普通成人自动目标。保留记录，由医生/注册营养师结合病史、用药、化验、成长或衰弱情况制定。不能调整药物、推断诊断或推荐补剂。
7. 总碳水、总糖和游离糖分开。游离糖为上限，不是补足目标；未知不记零。纤维参考至少 25g/d；食物建议强调多样性、蔬果、全谷物和豆类，不鼓励用补剂追数字。
8. 只有本人确认实际摄入份量的已完成估算进入统计。未记录不等于零。用户确认正餐/零食/饮料记全且所有餐食均可统计后，才给全天差额。新增、修改、删除餐食自动撤回完整日确认；重新估算需要再次确认份量。
9. 近七天显示每一天记录完整度及已记录范围，不把过去的差额累积成必须补吃的“欠账”，不鼓励跳餐、惩罚性运动或过度限制。

## 依据（读取 2026-10-04）

- WHO：<https://www.who.int/news-room/fact-sheets/detail/healthy-diet>。食物多样性、纤维、游离糖限制。糖 <10% 能量，进一步降至 5% 可能有额外获益。
- Mifflin–St Jeor 原始研究：<https://pubmed.ncbi.nlm.nih.gov/2305711/>。静息能量估算，不是照片推算。
- NIH/NIDDK：<https://www.niddk.nih.gov/bwp>。个人需求依赖体重、性别、年龄、身高和活动；规划器不适用未成年/孕哺。当前没有复刻其动态体重模型。
- EFSA：<https://www.efsa.europa.eu/en/press/news/120209>。普通成人蛋白质参考。
- ISSN：<https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/>。适用健康运动人群，不能外推到肾病等人群。
- NIDDK 肾病饮食：<https://www.niddk.nih.gov/health-information/kidney-disease/chronic-kidney-disease-ckd/healthy-eating-adults-chronic-kidney-disease>。
- NIDDK 糖尿病：<https://www.niddk.nih.gov/health-information/diabetes/overview/healthy-living-with-diabetes>。饮食须结合药物，不能仅凭照片调药。
- DeepSeek 图片 API：<https://api-docs.deepseek.com/guides/vision/>。复用已配置服务，先获得照片识别授权，只传已授权餐食照片及说明；不传身体资料。记录用量。

## 实现与验收

新增 062 迁移（四张小表与餐食变更触发器），复用现有 PostgreSQL、媒体鉴权、模型服务，无新增依赖/队列/域名。`/snapshot/v1/nutrition` 挂在现有登录鉴权之后，额外要求本人会话。任务持久状态+generation 防止旧请求回写覆盖新结果，输入摘要避免旧内容继续计入；3 分钟超时状态可显式重试。失败保留原记录和同输入旧结果。

Direction Gate：保护用户亲自提交的餐食与份量记录，AI 输出保持估算身份，不提升 Capability State、不冒充独立健康评估。Outcome Preview / Demonstration N/A（既有记录产品升级）。验收必须覆盖未知值、特殊人群、跨账户隔离、缓存、修改失效、完整度、图片实际识别、保存后重开。

尚未实现的能力：称重与条码/营养标签核对、营养师签发治疗目标、长期体重反馈自动校准。不得把这些说成现成功能。

## 手机图片上传中断修复（2026-10-05）

失败证据：00:30–00:32 的 iPhone Safari 餐食图片请求出现 499、408、499；服务器尚未完整接收图片，无图片处理异常。普通小图在真实网页上传成功，说明不是所有上传不可用。根因范围为移动上行传输超时/中断，不能仅凭日志断定具体网络设备故障。

修复：H5 在本机把较大图片缩至最长边 1600、JPEG 分档压缩，优先不超过 512 KiB；小图不重复压缩。使用现有上传接口的 120 秒超时。待上传原路径在当前编辑页保留，失败时可明确重试；成功项不重传，取消待传照片前不能误保存为完整记录。离开/刷新后不承诺恢复未上传草稿。不可解码格式提示转换 JPG，不谎报成功。

回归：新增压缩尺寸/字节目标/临时 URL 清理、无需处理的小图、不可解码格式、部分成功后重试不重复测试。原实现的失败保留测试先失败，修复后相关 27 项测试通过，生产构建通过。仅替换餐食页面与运行时映射，不改服务器存储或已保存餐食。

发布结果：`pages-snapshot-meal.abf4bc2c.js` / `index.f6aeeb40.js`，文件哈希已从公网核对。上线复查发现营养模块及路由挂载被后续服务器版本移除（旧 snapshot 路由哈希与初始版本一致）；已从本功能发布包恢复缺失模块及已鉴权挂载，保留已有数据，真实登录页面再次正常读取。普通测试图片上传预览通过且未保存餐食；大图真实浏览器测试因浏览器连接不可用未完成，不能宣称原 iPhone 场景已实测通过，需要用户原图复试。
