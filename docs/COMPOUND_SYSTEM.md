# Shroom 复利系统：从公共地图找到自己的长期投资

> 状态：当前产品基线
> 更新：2026-09-14

## 1. 定位

复利系统是日记之前的计划层，不是日记之后的 AI 提醒层。它不先问用户“你想做什么”，也不把任何目标包装成复利；它先给出一张经过筛选的公共复利地图，帮助用户从真正能积累、复用和放大的类型中，找到适合自己的少数项目。

产品链路是：

```text
公共复利地图
  → 用户的现实映射（私有）
  → 4 周验证（它真的会复利吗）
  → 12 周计划（时间、行动、取舍）
  → 待办（具体执行）
  → 日记（实时记录和复盘现实）
  → 本金、复用和回报证据
  → 继续、调整或停止
```

人生 OS 回答“什么才叫更好”；复利系统回答“接下来把时间投到哪里”。

## 2. 公共复利地图

公共地图是产品知识，不是为某个用户预置的人生目标。地图只收录能清楚回答三个问题的原型：

1. 持续投入会留下什么可复用的“本金”？
2. 这些本金如何让下一次更容易、更快、更好或触达更多人？
3. 回报如何进入下一轮，而不是每次归零？

当前地图包含两类：

- **增长复利**：能力与反馈、知识网络、决策校准、可复用资产、自动化系统、产品反馈、工作分发、信誉与信任、协作上下文、资本。
- **底盘保障**：身体容量、注意力容量、安全缓冲。它们未必直接产生增长回报，但会保护其他复利过程不被打断，因此不伪装成增长项。

每个原型都展示机制、适用情况、不算复利的反例、默认指标和可映射的例子。原型可版本化，修订公共地图不会偷偷改写用户已建立的私有计划。

## 3. 从原型到我的计划

用户选择原型后，基础表单只要求四个必须由用户决定的内容：

- **私有名称**：在我生活中的具体项目；
- **持续投入**：准备反复发生的投入方式；
- **12 周结果**：机制验证结束时能亲自核对的变化；
- **当前一步**：离开页面后可以开始的下一步。

本金、回报、再投入规则、双指标和首个里程碑由所选原型给出默认值。用户可在高级设置里修订指标、12 周次数、每周时间和不做清单，不需要先自行设计整套复利模型。

同时最多保留 3 项活动计划。这是为了保护真实的时间配置，不是要求人只做能产生未来回报的事。休息、陪伴、玩耍和当下体验可以有本身价值，无需伪装成复利。

## 4. 验证，而不是预言

新计划统一进入 **验证中**，默认验证 4 周。系统不因为用户选了一个原型，就宣布它已经产生复利。验证后由用户根据真实证据判断：

- **已形成复利**：已出现可复用或可观察回报；
- **暂时线性**：目前仍主要靠同等时间换结果；
- **底盘保障**：它保护长期容量，不宣称直接增长；
- **继续验证**：证据还不足。

“已形成复利”必须至少有一条用户确认的复用/回报记录，或回报指标已经发生变化。AI 不能自动宣布验证成功。

财务本金计划使用更严格的判断：页面显示“再投入机制已验证”，且必须存在一条由用户确认、关联既有本金、写明实际结果的 `RETURN` 记录。手动增加计数不能单独证明这一状态，“已验证”也不代表未来收益。

## 5. 每周管理和进度

每周对每项计划配置真实投入时间、1–5 个行动和本周不做的事。待办仍是唯一执行层，复利系统不复制第二套任务引擎。

进度同时看四类事实：

1. 资源投入：本周已投入时间；
2. 本金积累：留下了多少能被再次使用的东西；
3. 复用次数：旧积累是否真的改变了新一次行动；
4. 结果回报：是否出现用户、收入、决策质量、完成速度或风险下降等真实变化。

记录进展时，AI 只把用户原话整理成可纠正草稿；用户确认后才增加时间、本金或回报数值。“准备做”不能增加真实进度。偏差的价值是检查资源、瓶颈和计划质量，不是制造内疚。

## 6. 日记、AI 和人生 OS 的边界

- 日记仍然自然书写、快速保存，不加必填复利表单。
- 日记分析可以提供带原文证据的现实反馈，但不能自动建立、停止或完成计划。
- 只有用户主动点击整理进展、分析瓶颈或阶段回看时，才调用相应 AI。
- AI 只能建议；映射、指标、取舍、证据判断和验证状态均由用户确认。
- 人生 OS 可被读取为取舍背景，但复利系统不能自动改写或签发原则。

### 财务本金计划的强制服务边界

- 它是个人资金计划与事实记录工具，不是投资顾问、产品推荐或交易系统。
- 新建计划前必须明确确认风险与服务边界；确认版本写入该计划的 `START` 事件。
- 不收集完成该功能不需要的银行或证券账户、卡号、密码、验证码；财务表单和进展接口发现这类信息时拒绝保存。
- 财务计划调用 AI 时，服务端追加不可被用户覆盖的金融提示边界，并先隐藏上下文中的账户凭证。
- AI 不得输出具体产品推荐、买卖/持有/加减仓/定投/择时、目标价、仓位比例、资产配置、收益或行情预测、保本及确定回报。
- 模型输出即使越界，也会被服务端规则丢弃，改用固定的安全说明；事件同时记录合规策略版本及是否拦截。
- 阶段回看只要包含财务计划证据，也使用同一边界。

## 7. 数据、隐私与兼容

公共原型来自版本化代码目录；用户的名称、映射、时间、进度和证据保存在 Shroom PostgreSQL，并且仅通过登录会话中的 `user_id` 读写。私有计划不进入发现。

`server/sql/035_compound_archetypes.sql` 在原表上增加原型快照、投资类型、本金/回报/再投入定义、验证状态和双指标。历史计划标记为 `legacy_direction`，原地保留，不删除原 Life OS 条目、事件、结果或日记关联。新计划不再强制绑定旧的 20 条长期方向。

主要私有 API：

- `GET /api/compound/v2/archetypes`：读取版本化公共复利地图；
- `GET /api/compound/v2/home`：计划组合、验证状态、本周时间、指标与近期进展；
- `POST /api/compound/v2/threads`：从原型建立一项待验证的 12 周计划；
- `PATCH /api/compound/v2/plans/:id`：修订用户映射和双指标；
- `PATCH /api/compound/v2/plans/:id/validation`：由用户确认当前验证判断；
- `PUT /api/compound/v2/plans/:id/week`：保存本周时间、行动和不做清单；
- 原有进展、瓶颈、日记回看、阶段回看和导出接口保留。

## 8. 验收标准

1. 没有计划的用户先看到公共复利地图，而不是空白输入框或默认的个人方向。
2. 原型必须同时说清复利机制、适用情况和反例；增长复利与底盘保障清晰区分。
3. 新计划必须有用户自己的本金、回报、再投入、双指标、12 周结果和当前一步。
4. 新计划默认为“验证中”；没有用户确认的复用或回报证据，不能标记“已形成复利”。
5. 用户能同时看到时间投入、本金积累和回报变化；“准备做”不增加任何真实进度。
6. 其他账号不能读取或修改当前用户的映射、计划、时间和证据。
7. 历史复利计划保留在同一存储中，不因新地图丢失。

最终判断不是“用户给一个目标加了复利标签”，而是：用户是否能从一组真正可复利的机制中找到属于自己的投资，并用证据判断它值不值得继续。
