# Shroom 复利系统：产品与实现规范

> 状态：当前产品基线
> 更新：2026-09-13

## 1. 定位

复利系统帮助用户把一个长期方向持续推进成真实行动、结果和可复用积累。它的主路径是：

```text
选择一件事 → 确认本次结果与最小一步 → 直接行动 / 主动请求协助
        → 记录真实结果 → 区分必要、维护、积累、复用和回报
        → 用户确认下一步 → 下次从原位置继续
```

它不是 20 项待办、每日打卡、人生评分或无状态聊天。“人生 OS”仍是独立的原则模块，保存用户确认签发的少量跨情境判断标准。复利系统可以读取这些原则作为上下文，但不能自动新增、改写或退休原则。

## 2. 五类 20 个长期方向

迁移 `022_life_os_long_term.sql` 已保存的五类 20 项继续作为方向目录和日记证据归档，不丢失已有编辑、关注范围、日记关联和外部引用。数据库表名 `life_os_items` 暂时保留，只是为了无损迁移，不代表产品仍把长期方向称为人生 OS。

20 项只放在二级页。首次使用只突出少量有真实关联记录或此前关注的候选；用户也能进入完整目录选择任意一项。确认前不会自动创建 20 条推进记录或待办。同一时间最多保留 3 条活动推进，首屏只显示当前一条和少量其他活动推进。

方向使用三种推进方式，共享同一套状态结构，不制造三套系统：

| 类型 | 例子 | 推进方式 |
|---|---|---|
| 持续维护 | 运动、财务纪律、维护关系 | 确认最低可行安排，在合适时机回看执行和障碍 |
| 情境练习 | 接受纠错、减少较劲、兑现承诺 | 相关情境发生时复盘方法，下次相似情境检查是否尝试、是否有效 |
| 成果积累 | 教学交付、技术资产、成果案例 | 围绕具体成果连续推进，保留产出和实际使用结果 |

## 3. 主权复利交互

### 直接继续

只展开用户上次确认的当前一步，不调用 AI、不重新分析，也不把打开页面算成行动。用户可以把它安排到待办，或者做完后记录结果。

### 让它更容易 / 需要 AI 帮助

只有用户明确点击时才调用模型。“让它更容易”给出最小、正常、完整三个真实行动版本；“需要 AI 帮助”读取已确认目标、当前一步、以往事件、相关日记证据、已有引用和已确认原则，提供一次具体协助。所有建议显示依据、假设和未纳入信息，且不会自动改写当前一步；用户点击采用后才更新。

### 当前最大约束

用户先用一句话描述具体约束。系统据上下文区分缺材料、目标过大、方法失效、优先级降低、等待外部条件、身体或精力不足、方向存疑和尚不明确。模型提出调整建议，但不会自动替用户采用；信息不足时最多问一个必要问题。

### 今天不推进

用户可以进入当日安静模式，不需要说明理由，不改变主线、不丢失位置、不形成失败或扣分记录。用户当天可以随时恢复；次日自动恢复正常显示。

### 记录结果

复用文字、录音、语音转写和私密图片上传。AI 只生成可纠正草稿，首先区分准备做、已经做、有效果、尚未验证，再建议长期类型：

- 必要完成：事情做完了，但未形成长期积累；
- 维护基础：维护身体、关系、能力或系统状态；
- 形成积累：留下以后可以再次使用的成果；
- 使用积累：明确关联并使用一项本人已有积累；
- 出现回报：已有积累带来可观察的时间、质量、机会或生活收益。

用户确认后才更新“上次做到”“下一步”和推进状态。复用与回报必须关联本人已确认的“形成积累”结果；系统只有在发生复用后才显示“已经发生的复利”。所有结果仍会出现在“近期发生”，不会再把每次完成都包装成积累。

## 4. 日记联动

日记仍按原方式保存，不增加强制表单，也不被复利分析阻塞。正常 AI 分析最多提出 3 条带原文依据的复利方向关联。只有当关联方向正在推进时，首页才显示少量待处理提示：

- “回看这次”生成事实、推测、旧方法是否使用、效果和下次尝试的可编辑草稿；用户确认后才接入推进状态。
- “不是这件事”移除关联并保存忽略决定，重复分析不会重复创建同一条提示。

日记没写某件事不等于用户没做，系统不能据此判定失败。日记修改或删除后，相关来源会失效；已经确认的历史结论保留但明确标记来源失效，未确认草稿不再继续使用。

Codex 等连接数据源属于菇日记的用户级数据层，不属于复利系统。当前它只作为日记观察席的可选背景，不能单独创建复利方向关联、推进事件或结果。未来若接入阶段回看，仍必须保留外部来源编号并经用户确认。

## 5. 阶段回看

阶段回看只能由用户主动发起。模型只使用带来源编号的已确认推进事件和有效日记依据，整理：实际做了什么、留下了什么、什么方法有效、什么方法无效或尚未验证，以及继续、调整或停止的建议。无来源的模型结论会在标准化时被丢弃。

回看草稿可以修改，用户确认后才进入历史。它不自动停止任何推进、不创建待办、不修改人生 OS，也不把健康、关系、技术和教学资产压成统一分数。

## 6. 数据、隐私与 API

迁移 `server/sql/023_compound_progress.sql` 增加：

- `compound_threads`：正在推进的事情、目标、上次做到、卡点、当前一步和活动状态。
- `compound_events`：开始、协助、卡点、结果、日记回看、暂停、恢复和结束事件；草稿与确认状态分离。
- `compound_reviews`：带来源引用的阶段回看草稿与确认版本。

旧 `compound_checkins` 四账户记录保留在数据库和导出中，但不再占据复利系统首页。业务资料继续存在日记、待办、菇卡、困惑、原则和媒体原表；复利系统只保存必要摘要、结果或引用，不复制第二份业务数据。

主要私有 API：

- `GET /api/compound/v2/home`：首次候选或上次推进位置。
- `POST /api/compound/v2/starter`、`POST /api/compound/v2/threads`：生成并确认起点。
- `POST /api/compound/v2/threads/:id/continue`：用户主动请求 AI 协助或缩小行动。
- `POST /api/compound/v2/threads/:id/suggestions/:eventId/adopt`：用户确认采用建议。
- `POST /api/compound/v2/threads/:id/blocker`：分析最大约束，不自动采用调整。
- `POST|DELETE /api/compound/v2/quiet-day`：开启或撤销当日安静模式。
- `POST /api/compound/v2/threads/:id/results/draft` 与确认接口：整理并确认真实结果。
- 日记回看、阶段回看和导出接口均位于 `/api/compound/v2`。

所有查询只使用登录会话中的 `user_id`，默认仅本人可见，不进入发现。附件沿用私密媒体所有权检查。AI 调用进入已有用量账本，保存 token 和价格快照。

## 7. 验收标准

1. 首次进入无需配置 20 项即可选定一件事并开始最小一步。
2. 离开后再次进入，能看到上次做到、当前最大约束和下一步，不重述背景。
3. “直接继续”不调用 AI；AI 协助和约束建议必须经用户采用才能改变下一步。
4. 结果必须经用户确认；必要工作与真实复利不可混称，复用和回报必须关联本人已有积累。
5. 相关日记能进入已有推进过程，且可纠正、忽略、去重和随来源失效。
6. 用户可以选择今天不推进且不受惩罚；人生 OS 原则没有被长期方向覆盖或由复利系统自动改写。

最终判断不是页面是否打开，而是：它是否帮助用户真正做成一步，并让下一次不必从零开始。
