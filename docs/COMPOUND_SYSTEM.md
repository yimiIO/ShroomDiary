# Shroom 复利系统：从公共地图找到自己的长期投资

> 状态：当前产品基线
> 更新：2026-09-17

## 1. 定位

复利系统是日记之前的计划层，不是日记之后的 AI 提醒层。它不先问用户“你想做什么”，也不把任何目标包装成复利；它先给出一张经过筛选的公共复利地图，帮助用户从真正能积累、复用和放大的类型中，找到适合自己的少数项目。

产品链路是：

```text
公共复利地图
  → 用户的现实映射（私有）
  → 首个观察周期（4 / 8 / 12 / 24 周）
  → 证据回看（它真的在复利，或正在保护底盘吗）
  → 待办（具体执行）
  → 日记（实时记录和复盘现实）
  → 本金、复用和回报证据
  → 继续、调整或停止
```

人生 OS 回答“什么才叫更好”；复利系统回答“接下来把时间投到哪里”。

## 2. 公共复利地图

公共地图是产品知识，不是为某个用户预置的人生目标。地图只收录能清楚回答三个问题的原型：

1. 持续投入会留下什么可复用的“本金”？
2. 这些本金如何让下一次更容易、更快、更好或触达更多人？
3. 回报如何进入下一轮，而不是每次归零？

当前地图包含两类：

- **增长复利**：能力与反馈、知识网络、决策校准、可复用资产、自动化系统、产品反馈、工作分发、信誉与信任、协作上下文、资本。
- **底盘保障**：身体容量、注意力容量、安全缓冲。它们未必直接产生增长回报，但会保护其他复利过程不被打断，因此不伪装成增长项。

每个原型都展示机制、适用情况、不算复利的反例、默认指标，以及至少两个可直接套用的起步案例。每个案例必须同时写清“能观察到什么”和“能感受到什么”：前者防止把愿望当进步，后者让长期投入在生活里有反馈、容易坚持。原型可版本化，修订公共地图不会偷偷改写用户已建立的私有计划。

## 3. 从原型到我的计划

用户选择原型后，必须先看到完整说明与起步案例，再选择“用这个案例开始”或“不套案例，自己创建”。案例只是可修改的脚手架，不替用户决定目标。基础表单只要求四个必须由用户决定的内容：

- **私有名称**：在我生活中的具体项目；
- **持续投入**：准备反复发生的投入方式；
- **周期结果**：首个观察周期结束时，能亲自观察或感受到的变化；
- **当前一步**：离开页面后可以开始的下一步。

本金、回报、再投入规则、双指标和首个里程碑由所选原型给出默认值。用户可选择 4、8、12 或 24 周作为首个观察周期，并在高级设置里修订指标、本周期次数、每周时间和不做清单，不需要先自行设计整套复利模型。

**12 周不是复利期限。** 它只是一种常用的首轮观察窗口；长期计划不会到期自动结束。短反馈明显的注意力边界或备份演练可以从 4 周开始，技能、产品与协作常用 8–12 周，现金缓冲等慢变量可以从 24 周开始。到期只触发继续、调整、暂停或换观察方式的回看。

身体与恢复底盘只管理睡眠、活动、恢复与可持续容量。若用户想理解持续症状从何时开始、什么情况下加重或减轻，应进入“身心记录”的健康长期观察，不在复利系统里推演疾病或原因。

同时最多保留 3 项活动计划。这是为了保护真实的时间配置，不是要求人只做能产生未来回报的事。休息、陪伴、玩耍和当下体验可以有本身价值，无需伪装成复利。

## 4. 验证，而不是预言

新计划统一进入 **验证中**，默认验证 4 周。系统不因为用户选了一个原型，就宣布它已经产生复利。验证后由用户根据真实证据判断：

- **已形成复利**：已出现可复用或可观察回报；
- **暂时线性**：目前仍主要靠同等时间换结果；
- **底盘保障**：它保护长期容量，不宣称直接增长；
- **继续验证**：证据还不足。

“已形成复利”必须至少有一条用户确认的复用/回报记录，或回报指标已经发生变化。AI 不能自动宣布验证成功。

财务本金计划不使用这套「已形成复利／暂时线性」判断。它独立呈现计划状态、记录状态和资金表现；首个观察周期只验证范围、记录、解释与核对机制是否可运行，不以盈利、分红或手动再投入判定成功。详细口径见 [FINANCIAL_COMPOUND_LEDGER.md](./FINANCIAL_COMPOUND_LEDGER.md)。

## 5. 每周管理和进度

每周对每项计划配置真实投入时间、1–5 个行动和本周不做的事。待办仍是唯一执行层，复利系统不复制第二套任务引擎。

进度同时看四类事实：

1. 资源投入：本周已投入时间；
2. 本金积累：留下了多少能被再次使用的东西；
3. 复用次数：旧积累是否真的改变了新一次行动；
4. 结果回报：是否出现用户、收入、决策质量、完成速度或风险下降等真实变化。

记录进展时，AI 只把用户原话整理成可纠正草稿；用户确认后才增加时间、本金或回报数值。“准备做”不能增加真实进度。偏差的价值是检查资源、瓶颈和计划质量，不是制造内疚。

财务本金计划例外：不参与每周时间与次数进度，进入独立的私人事实台账，按月核对资金流与市值，按季度回看持有结构、规则版本和用户对偏离的解释。

## 6. 日记、AI 和人生 OS 的边界

- 日记仍然自然书写、快速保存，不加必填复利表单。
- 日记分析可以提供带原文证据的现实反馈，但不能自动建立、停止或完成计划。
- 只有用户主动点击整理进展、分析瓶颈或阶段回看时，才调用相应 AI。
- AI 只能建议；映射、指标、取舍、证据判断和验证状态均由用户确认。
- 人生 OS 可被读取为取舍背景，但复利系统不能自动改写或签发原则。

### 财务本金计划的强制服务边界

- 它是个人资金计划与事实记录工具，不是投资顾问、产品推荐或交易系统。
- 创建顺序固定为：长期期限 → 投入规则、周期与金额 → 用户自选标的或方向 → 记录起点与核对频率；不能先创建空账本再要求用户自己寻找计划入口。
- 计划标的与真实持有是两个对象：前者进入可修订的规则版本，后者只有在用户确认日期和金额后才进入持有结构。
- 新建计划前必须明确确认风险与服务边界；确认版本写入该计划的 `START` 事件。
- 不收集完成该功能不需要的银行或证券账户、卡号、密码、验证码；财务表单和进展接口发现这类信息时拒绝保存。
- 财务计划调用 AI 时，服务端追加不可被用户覆盖的金融提示边界，并先隐藏上下文中的账户凭证。
- AI 不得输出具体产品推荐、买卖/持有/加减仓/定投/择时、目标价、仓位比例、资产配置、收益或行情预测、保本及确定回报。
- 模型输出即使越界，也会被服务端规则丢弃，改用固定的安全说明；事件同时记录合规策略版本及是否拦截。
- 阶段回看只要包含财务计划证据，也使用同一边界。
- 精确金额与持有内容使用独立密钥加密保存；财务 API 仅允许登录会话访问，不向 API Token 开放。
- 普通财务核算不调用模型；财务 AI 文本整理默认关闭，启用前必须明确披露实际处理方并取得可撤回的单独授权。

### 移动端信息层级

- 首屏只呈现今天最值得推进的一步，不默认展开复利原理、双指标、周计划和全部历史记录。
- 计划详情、近期进展和日记反馈由用户主动展开；关闭后恢复紧凑状态。
- 公共方向库先显示少量候选和名称；选中后在同一层完整显示机制、适用说明、反例、指标和可感知案例，再允许创建，避免用户在没理解时直接进入空表单。
- 资金计划使用四步创建：目的与期限 → 投入方式与金额 → 用户自选方向与记录起点 → 隐私和合规确认。每屏只要求完成当前一步。
- 用户界面使用“资金变动”“某天的总金额”“实际赚亏”等普通语言；`snapshot`、`ledger` 等词只保留在数据模型和接口内部。

### 删除计划

- 每一种复利计划都可以由所属用户永久删除，不把“停止”和“删除”混为一谈。
- 删除入口位于计划卡片的管理菜单，使用跨端自定义慎重确认界面；必须输入完整计划名称，并提交固定的永久删除确认语句。
- 删除计划会级联删除该计划的进度、证据、周配置和专属财务台账；不会删除原始日记、人生 OS 或待办。已有待办只解除计划关联。
- 若删除的是当前主计划，系统从剩余活动计划中选择最近推进的一项作为主计划；删除请求只能使用登录会话对应的用户身份。

## 7. 数据、隐私与兼容

公共原型来自版本化代码目录；用户的名称、映射、时间、进度和证据保存在 Shroom PostgreSQL，并且仅通过登录会话中的 `user_id` 读写。私有计划不进入发现。

`server/sql/035_compound_archetypes.sql` 在原表上增加原型快照、投资类型、本金/回报/再投入定义、验证状态和双指标。历史计划标记为 `legacy_direction`，原地保留，不删除原 Life OS 条目、事件、结果或日记关联。新计划不再强制绑定旧的 20 条长期方向。

`server/sql/038_financial_ledger.sql` 为财务本金计划增加独立台账。旧版次数、金额描述和验证标记原地保留，但不自动折算或迁入新台账。

资金计划允许用户选择两种真实起点：

- **补录历史**：逐笔填写过去已经发生的日期、金额、来源、平台和具体产品；系统按日期核算，原始时分秒可保留在备注中。
- **从今天开始**：不重建全部历史，只把今天计划范围内的总金额作为第一条基准。之后继续记录投入、取出和新的总金额，可以计算从今天起的赚亏，但不能反推出过去的累计收益。

两种方式都由用户主动选择。系统不能把当前总金额误写成“历史投入”，也不能根据基金名称或当前金额猜测过去的买入明细。

当前持仓使用同一份数据提供三种核对口径：整体总览、按渠道、按标的。每种口径均展示投入本金、当前余额和涨跌；同一渠道与标的的旧持仓快照只保留为历史，不重复进入当前合计。任一明细缺少本金时，上级汇总不得显示伪造的总涨跌。

主要私有 API：

- `GET /api/compound/v2/archetypes`：读取版本化公共复利地图；
- `GET /api/compound/v2/home`：计划组合、验证状态、本周时间、指标与近期进展；
- `POST /api/compound/v2/threads`：从原型建立一项待验证的长期计划，并保存首个观察周期；
- `PATCH /api/compound/v2/plans/:id`：修订用户映射和双指标；
- `PATCH /api/compound/v2/plans/:id/validation`：由用户确认当前验证判断；
- `PUT /api/compound/v2/plans/:id/week`：保存本周时间、行动和不做清单；
- 原有进展、瓶颈、日记回看、阶段回看和导出接口保留。
- `/api/compound/v2/financial/plans/:id/*`：财务设置、资金事件、快照、持有、规则、回看、导出和删除；只允许当前登录会话访问。

## 8. 验收标准

1. 没有计划的用户先看到公共复利地图，而不是空白输入框或默认的个人方向。
2. 原型必须同时说清复利机制、适用情况和反例；增长复利与底盘保障清晰区分。
3. 新计划必须有用户自己的本金、回报、再投入、双指标、首个观察周期结果和当前一步。
4. 新计划默认为“验证中”；没有用户确认的复用或回报证据，不能标记“已形成复利”。
5. 用户能同时看到时间投入、本金积累和回报变化；“准备做”不增加任何真实进度。
6. 其他账号不能读取或修改当前用户的映射、计划、时间和证据。
7. 历史复利计划保留在同一存储中，不因新地图丢失。
8. 手机首屏不展开完整计划、全部方向与全部历史；主要正文不小于 28rpx，主要操作具备至少 82rpx 的触控高度。
9. 资金计划界面不要求用户理解“台账”或“快照”等内部术语，且创建过程一次只填写一个阶段。
10. 每个原型至少提供两个可修改案例，并同时说明可观察证据、可感受变化和第一步；用户也可以完全不套案例。

最终判断不是“用户给一个目标加了复利标签”，而是：用户是否能从一组真正可复利的机制中找到属于自己的投资，并用证据判断它值不值得继续。
