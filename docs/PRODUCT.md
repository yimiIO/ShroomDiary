# Shroom 产品定义

> 状态：当前产品基线
>
> 更新：2026-09-14
>
> 适用：产品设计、前后端实现、AI 提示词、数据迁移与验收

## 1. 远景、目标与当前阶段

### 1.1 远景

> 不遗忘你，也不替你生活；在真正需要时，带回恰当的记忆与帮助。

Shroom 的远景是成为每个人长期陪伴的 AI 伙伴。它不是一个等待用户提问的聊天窗口，而是在用户明确授权的边界内，随时间理解这个人的经历、选择、关系、困惑、判断标准与长期目标，并在合适时机提供及时的帮助、辅助、提醒和新的观察。

Shroom 希望减少人对自己经历的遗忘，帮助人不必在每次遇到相似处境时重新从零开始；也不急于替人下结论，而是让新的经历持续校正旧的理解。

### 1.2 目标

Shroom 要建立的不是“记录得越多越好”的人生数据库，而是一个可信的个人记忆与辅助系统：

1. **保留重要的真实**：在经历被遗忘或重写之前，留下可回到原文的个人记忆。
2. **随时间形成理解**：连接分散的经历，发现反复模式、反例、未解之问和真正发生的变化。
3. **在正确时机介入**：不追求 AI 一直说话，只在一条过去经验、承诺、关系线索或长期目标对当下真正有帮助时提醒。
4. **保留人的决定权**：AI 负责记忆、检索、比较和提出候选；意义、采纳、行动和公开仍由用户决定。
5. **让记忆属于用户**：用户可以查看系统知道什么、纠正理解、撤回授权、删除内容并导出自己的数据。

### 1.3 从日记到人类 AI 伙伴

```text
当前：用户主动记录
  → 近期：AI 帮助整理、找回、连接和回看
  → 中期：低摩擦捕捉候选经历与线索，由用户确认什么值得留下
  → 远期：在合适情境中主动带回过去的经验、提醒与支持
```

当前版本仍把用户主动写入的日记作为个人经历的核心原始记录，并以 Codex 作为第一个可选用户数据源，保留没有写进日记的最小任务事实。外部活动始终与用户亲笔日记、AI 派生解释分层存储和展示。这是验证信任、用户意图和记忆准确性的起点。降低记录摩擦必须同时满足：

- 用户明确选择哪些来源可以进入 Shroom；
- 采集状态始终可见，可随时暂停或撤回；
- 原始数据最小化保留，可以查看、更正、删除和导出；
- 自动捕捉首先产生候选线索，不自动上升为对人的结论；
- 提醒应可解释“为什么现在出现”，且用户可以关闭同类提醒。

### 1.4 产品是什么

Shroom 是一款以私人日记为原点的 AI 记忆、理解与轻社交产品。它帮助用户保存真实经历，在需要时找回和讨论过去，从经历中形成可复用的理解，并逐步澄清自己认可的判断标准。

它不是通用笔记、内容社区、心理诊断工具，也不是把每段日记自动加工成建议的 AI 流水线。

产品核心链路是：

```text
记录经历 → 找回与讨论 → 形成理解 → 校准判断标准 → 用户决定是否行动或分享
   日记         回看          菇卡          人生 OS             待办 / 发现
```

AI 在这条链路中负责检索、比较、提出假设和解释依据；用户始终拥有原始经历、最终含义、是否采纳以及是否公开的决定权。

## 2. 产品承诺

Shroom 应长期保护以下四件事：

1. **经历不被改写**：日记是用户当时经验的原始记录，AI 结果只能作为派生内容存在。
2. **理解可以追溯**：重要结论应能回到具体日记或用户自己的菇卡，不用空泛的人格标签代替证据。
3. **用户拥有解释权**：AI 可以提出候选理解，不能替用户定义身份、价值观或人生方向。
4. **私密默认、公开明确**：日记、媒体、人生 OS 和新菇卡默认私密；只有用户明确选择的菇卡进入发现。

## 3. 核心对象与边界

| 对象 | 它回答的问题 | 产品定义 | 它不是什么 |
|---|---|---|---|
| 日记 | 当时发生了什么？ | 对经历、感受与想法的原始记录 | AI 结论或公开动态 |
| 数据源连接 | 哪些已授权系统可以为我提供活动线索？ | 用户级的授权、同步、用途和撤回设置 | AI 复利功能或隐形监听 |
| 外部活动 | 已连接工具中观测到了什么？ | 与日记分开、来源可见的最小事实 | 用户主观感受、人工专注时长或 AI 结论 |
| 回看对话 | 我的过去与此刻有什么关系？ | 基于本人日记、带来源引用的搜索和讨论 | 只靠标签或关键词匹配的搜索框 |
| 未解之问 | 哪些问题需要时间和新经历才能理解？ | 跨日记积累用户确认的证据，并保存可修订的阶段理解 | 日记分类、待办或一次性 AI 问答 |
| 观察席分析 | 这一次还可以怎样理解？ | 针对本次日记、由用户选择角度的多席观察 | 心理诊断或唯一答案 |
| 菇卡 | 下次遇到相似时刻，我想带着什么理解？ | 可复用的理解、提醒或观察视角 | 行动、待办、承诺或人生原则仓库 |
| 人生 OS | 对我而言，什么才叫“更好”？ | 少量、当前生效、由用户签发的判断标准、边界和复盘问题 | 性格报告、AI 定义的身份或无限增长的语录集 |
| 复利系统 | 接下来的时间应该投到哪里？ | 最多 3 项 12 周计划的复利机制、时间配置、领先指标、结果证据、瓶颈和不做清单 | 20 条待办、每日打卡、人生总分或 AI 提醒流 |
| 待办 / 实验 | 接下来具体做什么？ | 有明确行动含义、可以完成的用户承诺 | 菇卡或人生 OS |
| 人脉 | 我怎样理解并维护一段关系？ | 私人的关系档案、互动、里程碑与提醒 | 通讯录复制品或公开社交关系图 |
| 发现 | 哪些他人的理解值得共鸣？ | 只展示用户明确公开的菇卡 | 日记广场或泛内容信息流 |

最重要的区分是：

> 菇卡帮助我在具体时刻做得更好。
>
> 人生 OS 帮助我决定什么才叫“更好”。

菇卡中可以包含“如何使用这份理解”的提示，也可以记录后来怎样实践，但这不改变菇卡的本体：它仍然是一份理解，而不是行动对象。真正需要执行、截止或完成状态的内容进入待办/实验系统。

## 4. 信息架构

一级导航固定为：

- **日记**：写日记、日历、按日回看、归档、搜索与 AI 记忆讨论。
- **菇卡**：管理自己的可复用理解与使用记录。
- **发现**：浏览、共鸣、收藏和复制被明确公开的菇卡。
- **我的**：账户、年度记录反馈、数据与连接、复利系统、待办、人脉、关系提醒、人生 OS 与数据导出。

模式候选层不是一级页面。AI 对“似乎反复出现”的判断应以“待观察”存在于回看或人生 OS 整理流程中，带支持证据、反例和不确定性；没有足够价值时不需要单独产品化。

未解之问也不增加一级页面：日记首页只展示当前问题入口，完整管理放在「我的」，写日记时提供可选关联。它不制造「困惑日记」分类，也不依赖标签筛选。

一次性承诺由待办/实验承载；跨多次的时间投资、进度判断与取舍由复利系统承载。日记保留实时发生与复盘，三者不互相复制。

## 5. 当前产品能力

以下是截至 2026-09-09 已进入代码或生产环境的能力。

### 5.1 账户与会话

- 手机号和密码注册、登录。
- 短期访问令牌配合可轮换刷新令牌；访问令牌过期时静默续期，默认连续登录期为 90 天。
- 前端协调同页并发刷新，服务端为 H5 多标签页同时轮换保留 30 秒容忍窗口；正常换令不向用户表现为重新登录。
- 每个请求从登录会话或受限 API Token 确认用户身份，不接受客户端传入 `userId` 选择数据。
- 短信登录、短信找回和第三方登录尚未启用。

### 5.2 日记与媒体

- 支持日期、可选具体时间或全日记录、心情、图片、语音和隐私状态；不要求用户手工给私密日记分类。
- 日历首次打开即加载当月记录；归档使用分页加载，避免一次拉取全部历史数据。
- 历史日记未配置时间时保持为全日记录，不伪造 23:00。
- 语音先私密保存，再由用户主动发起高精度转写；转写结果可编辑，只有用户点击加入正文并保存后才成为日记内容。
- 图片在服务端校正方向、移除 EXIF/GPS，并按内容选择无损或高质量 WebP；处理后的文件不得大于原文件，否则保留更小且安全的版本。

### 5.3 回看与日记记忆

- 支持从顶部进入对本人日记的搜索与讨论，也支持写完日记后发起“与这次经历相关的过去”讨论。
- 检索不是只看心情标签或关键词：系统使用文本检索、向量召回、模型语义判断和原文引用回答跨日记问题。
- 回看先用一句话交付整体发现，每条观察也先显示一句可扫读的判断；详细解释、来源、解释边界和完整时间线由用户按兴趣展开。系统可以找到多条有证据的发现，但不能把二次提炼重点的负担交还给用户。
- 回答保存来源清单和引用；用户可以标记“不是同一件事”“理解错了”“现在不想谈”或“有帮助”。
- 日记正文改变时，派生索引和旧分析按版本失效，不覆盖原始日记。
- 归档中的“成长 / 情绪 / 关系 / 工作 / 旅行 / 灵感”是稳定的语义回看口径，不是日记标签。首次打开盘点正文，之后仅增量分析新增或修改的日记。

### 5.4 AI 分析、菇卡与行动

- 每个新用户默认拥有第一性原理、熵增/熵减、人生复利、人生 OS 对照与生物驱动五个观察席；用户可以暂停默认席位，并创建、编辑、启停或删除自己的观察席。
- 每次观察开始时固化当时启用的席位快照，后续修改个人设置不会改写历史分析；自定义席位与默认席位共享“只依据正文、区分事实与解释、不替用户下结论”的边界。
- 观察席分析由已配置的 AI 服务生成，结果与原日记分开存储。启用席位越多，单次分析的模型调用与成本通常越高。
- 每次日记观察和每次回看都记录供应商返回的输入、缓存命中/未命中、输出及总 token，并保存调用发生时的公开价格快照。DeepSeek 页面直接展示易懂的人民币预计花费；优惠额度、税费和供应商最终扣费不伪装为产品可确认的精确账单。
- 上线记账前发生的历史 AI 调用没有 usage 记录，不做虚假的费用回填。
- AI 可以建议创建私密菇卡、绑定已有菇卡或创建待办，但三者都需要用户明确确认。
- 保存日记不会自动生成菇卡；分析完成后只提示可选动作。
- 菇卡支持私密、匿名公开、实名公开、共鸣、收藏、复制和后续使用记录。
- 从他人的公开菇卡复制时，创建属于当前用户的新副本，不共享私密所有权。

### 5.5 未解之问

- 用户可以保存暂时无法靠一次讨论回答的长期问题，并补充背景。
- 日记只有在用户写作时明确选择后才成为问题线索；一篇日记最多关联三个问题，不静默抓取浏览器历史或外部数据。
- 问题积累至少两条允许 AI 读取的线索后，用户可以主动复盘。AI 同时整理支持、反例、变化、未知项和下一次值得观察的内容。
- 新增三条线索，或已有新线索且上次复盘超过 14 天时，产品只提示「适合再看看」，不会自动消费 API 或覆盖结论。
- 每次复盘形成不可变版本并计入独立 token/人民币费用账本；问题是否继续、暂停或已经想明白只能由用户确认。
- 详细机制见 [INQUIRIES.md](./INQUIRIES.md)。

#### 发现广场与公开菇卡

- 发现广场和个人菇卡的卡片浏览统一使用单张左右翻阅；纵向滚动留给页面信息和完整详情。个人菇卡仍是自己的理解库，详情承担编辑、练习和引用到日记，不把社交热度变成个人库的排序标准。
- 点开公开菇卡后，访客只能看到作者主动公开的觉察句、个人理解、使用提示、标签、选择的署名方式，以及共鸣、收藏、引用等聚合计数。
- 原始日记、日记来源 ID、AI 分析来源、私人练习内容和个人练习次数不属于公开卡片，不能因为菇卡公开而被带到广场。
- **共鸣**表示“这份理解也击中了我”，是可取消的轻量公开反馈，不产生菇卡所有权，也不能对自己的卡共鸣。
- **收藏**是当前用户的私密书签，可以取消；收藏不会复制内容，也不会让原作者看到收藏者的私人记录。
- **引用到我的菇卡**会保存一个属于当前用户的私密快照，并以 `copiedFromId` 保留来源。重复引用同一公开卡返回已有副本，不制造重复卡。

#### 人物档案与普通用户使用同一种菇卡

- 菇卡不因来源不同而拆成两种产品类型。「人类留给自己的提醒」中的卡片就是人物模拟用户公开的普通菇卡，使用相同的卡片结构、浏览方式、共鸣、收藏、引用和练习链路。
- 历史人物是日记、手稿等材料的来源；现代觉察句、解释和使用提示由 Shroom 转译形成。人物姓名可以作为档案昵称，但来源详情必须说明这是 Shroom 建立的只读人物档案、并非本人注册或逐字发布。
- 每位历史人物使用一个不可登录的只读用户档案，名字使用真实姓名；相关菇卡通过正常 `user_id` 归属该档案，与普通用户卡共用 `users`、`cards` 和全部社交关系表。
- 详情仍保留作品、位置与 Shroom 转译说明，用于区分“卡片归属人物”与“文字是历史原句”这两个不同事实。
- 人物集合只保留为内部来源与运营元数据，不在发现页生成独立专题卡或第二套入口；人物菇卡直接与其他用户公开菇卡共同展示。
- **练习别人的卡**必须先产生自己的私密副本；后续修改、练习记录和日记关联全部写在自己的数据空间，不改写原作者的卡。
- 被引用后的个人副本可以直接带入新日记。这里的“引用”是有来源的个人化复用，不是把别人的卡或日记共同编辑。

### 5.6 人生 OS

- 人生 OS 已升级为按条原则管理：每条包含领域、判断标准、适用边界、复盘问题、形成方式、置信状态、支持依据和反例。
- AI 整理只生成待确认提案，不直接改写当前版本。
- 用户可以逐条编辑、排除、合并采纳，并明确选择是否把具体情境理解另存为私密菇卡。
- 签发后生成新版本，旧版与来源引用保留；当前生效原则建议 5–9 条，当前硬上限 50 条。
- 详细机制见 [LIFE_OS.md](./LIFE_OS.md)。

### 5.7 人脉与关系维护

- 每个用户拥有隔离的关系档案、互动记录、评分历史、关系待办、里程碑和提醒设置。
- 保存或修改已授权 AI 的日记后，后台从正文证据整理具体人物与互动事件。模型只能提出已允许的评分规则代码，实际加减分由程序确定，不采信模型自报分值。
- 人脉整理按日记版本幂等；重试不会反复加分，编辑、删除或撤回 AI 授权时会回滚原版本自动写入的事件、评分和承诺待办。
- 月度关系回顾与提醒属于用户的私人辅助，不进入发现广场，也不自动影响人生 OS。

### 5.8 数据导出与个人 Agent

- 用户可以导出自己的日记、菇卡、关系、待办、分析、人生 OS、人生 OS 原则和整理提案。
- Shroom 龙虾/个人 Agent 使用独立、可撤销、仅保存摘要且按资源授权的 API Token；不能使用账户密码或浏览器刷新令牌代替。

### 5.9 用户数据源

- 「我的 → 数据与连接」是用户级入口；Codex 是第一个数据源，不归属于复利系统。
- 用户可查看状态和最近同步；Codex 每天 19:00 增量同步，关机或休眠错过后在本机恢复运行时补拉。用户分别控制是否显示在日记时间线、是否允许 AI 日记分析读取。
- 只同步经脱敏的任务名、项目简称、开始/结束、运行时长与结果状态；不同步对话、回答、工具调用、文件内容或绝对路径。
- 外部活动是观测事实，不写入日记正文；任务运行时间不等于用户的人工专注时间。
- 暂停、断开、删除和导出都是显式用户操作。删除数据源记录时，使用它们的旧 AI 分析一并失效。详见 [DATA_SOURCES.md](./DATA_SOURCES.md)。

### 5.9.1 菇每日总结

- 用户可以主动打开某一天的每日总结。首屏必须先展示“今天最需要修正的问题、继续下去的代价、下一次具体怎么改”，随后才展示不该亲自做的事、人生 OS 对照、复利判断；完成项与正面事实压缩后放在末尾作为依据，不能把总结写成成绩单。
- 总结只读取该用户当天允许 AI 使用的日记、Codex 活动、已完成待办，以及已签发人生 OS 与当前复利计划；所有判断保存来源引用和数据截止时间。
- Codex 任务完成不等于现实结果完成，没有记录也不等于没有行动。证据不足时必须保留“证据不足”，不能补造结论。
- 每天只选择一个最值得纠正的问题和一个一致的明日调整；优先识别人生 OS 偏离、只有活动而没有结果/复用证据、应停止或委派的重复劳动。没有可靠证据时必须明确无法指出具体失误，不能为了显得尖锐而编造批评。
- 总结是派生草稿，不写入日记正文，不自动修改人生 OS、复利状态或待办。
- 当天存在可读取证据且用户开启站内投递时，系统在上海时间 22:00 把总结放入私有收件箱；未读数显示在「我的」与应用角标中，打开总结即标记已读。站内投递不依赖邮箱。
- 用户验证邮箱并显式开启后，如果当天从未打开总结，系统在上海时间 22:00 生成并发送邮件；已经打开则跳过。邮件通道未配置时网页总结仍可用，系统不得假装已发送。

### 5.10 复利系统

- 入口首先展示版本化的公共复利地图，引导用户从能力与反馈、知识网络、决策校准、可复用资产、系统、信任、资本等真实机制中选择，而不是把用户随意输入的愿望包装成复利。
- 公共地图区分“直接产生积累”和“保护长期底盘”；休息、陪伴和当下体验无需伪装成复利项。
- 每位登录用户可从原型创建最多 3 项私有计划。每项必须映射自己的本金、回报、再投入、本金指标、回报指标、12 周结果、证据、每周时间、下一步和不做清单。
- 新计划默认进入 4 周验证。没有用户确认的复用或回报证据，不能宣布“已形成复利”；用户也可将它判定为线性项或底盘保障。
- 复利首页同时显示计划时间/真实投入、本金积累、复用/回报指标、验证状态、本周行动和取舍。
- 本周配置有 1–5 个行动，可以加入已有待办系统。时间偏差是检查资源和计划质量的信号，不是人生得分。
- 进展只在用户确认后增加实际投入、本金或回报指标；“准备做”不计入进度。
- 日记是真实发生与复盘层，可为计划提供现实反馈，但不自动新建、完成或停止计划。
- 人生 OS 保持为独立原则模块；复利系统可读取已确认原则，但不能自动改写或签发。详见 [COMPOUND_SYSTEM.md](./COMPOUND_SYSTEM.md)。
- 财务本金复利使用独立的私人事实台账，以金额、资金来源、市值、实际持有和用户自己的规则版本回答「投入多少、实际赚亏、持有什么、是否偏离」。它不使用通用次数进度或「复利已出现」判断，不提供产品、配置和交易建议；详见 [FINANCIAL_COMPOUND_LEDGER.md](./FINANCIAL_COMPOUND_LEDGER.md)。

### 5.11 待办与项目

- 待办是唯一行动层：复利系统和日记 AI 只能经用户确认后建议或预填同一个任务实体，不复制列表。
- 标题是创建任务的唯一必填项。状态、项目、安排日期、截止日期、重复规则、复利方向和结果相互独立。
- 重复待办由规则和独立发生实例组成；跳过、完成和实际结果不互相冒充。修改未来安排不覆盖过去已完成记录。
- 完成任务生成独立、可撤销的系统行动记录，可在每日记录中查看，但不冒充用户的日记正文。
- 项目只组织同一套待办。完成项目不自动完成任务，归档前必须处理未完成任务的去向。详见 [TODO_PROJECTS.md](./TODO_PROJECTS.md)。

### 5.12 菇点、活动与高级功能

- 注册与写日记免费。连续 7 个上海自然日各完成至少一篇日记后，账户一次性获得 1 菇点；补写历史日期不倒推活动天数，同一用户只能领取一次。
- 「我的七日变化」分享卡只展示连续天数和日期范围，不读取或展示日记正文。是否生成、保存或分享完全由用户决定，分享本身不触发奖励，也不作为领取条件。
- 复利系统、未解之问和身心问题分别以 10 菇点永久解锁。功能解锁费不包含后续 AI 调用成本；服务端鉴权是最终权限来源，客户端隐藏入口不能替代鉴权。
- 1 元充值为 1 菇点，常用充值金额为 10 / 20 / 50 / 100 元，并允许 1–500 元自定义金额。充值菇点与活动赠送菇点分账记录，消费时优先使用赠送菇点。
- 用户主动发起的收费 AI 调用按供应商当次成功调用的人民币成本乘以 2.5 扣除菇点。首次收费调用前必须明确接受当前收费与退款规则；未同意时不发起模型请求。页面如实显示供应商返回的输入、缓存和输出 Token，以及实际扣除菇点；失败输出、网络失败和系统重试不向用户扣费。
- 收费 AI 调用前按当前模型高峰期、未命中缓存单价和最大输出上限计算保守授权额度；余额不足时不发起请求，并统一引导到「菇点与账单」。授权额度不预扣，成功后只扣实际用量；超出授权上限的供应商异常用量由平台承担，不形成用户欠额。
- 收款、退款和开票主体必须使用同一个法定名称。生产收款只有在法定主体、客服方式、互联网信息服务资质、APP/小程序备案、微信支付商户号、应用标识、验签公钥/证书与支付和退款回调地址全部配置且人工复核一致时才可启用；`suyetiyu` 只是后台商户标签，不能替代法定主体名称。
- H5 仅在个人微信内使用与 `suyetiyu` 商户绑定公众号的 JSAPI 支付；系统浏览器和企业微信不开放充值。菇点与功能解锁属于虚拟服务；微信小程序在虚拟支付能力审核并独立接入前，不显示充值按钮、不调用普通 `requestPayment`，也不引导用户跳转 H5 付款。
- 用户协议、隐私政策、充值规则、退款规则和接受记录均可查看并随个人数据导出。未消费的充值菇点可以申请原路退款；活动赠送、已消费 AI 成本和已履约的数字功能按规则不作为未消费余额退款。退款只有在微信回调或主动查单确认成功后才核销钱包，处理中或异常状态继续冻结对应余额。
- 完整计费、对账、退款与上线门槛见 [BILLING.md](./BILLING.md)。

## 6. 数据与隐私边界

Shroom 只有一个运行时业务真相源：独立 PostgreSQL 数据库。用户明确连接的 Codex 等外部数据源只是受控输入；同步后形成带用户归属和来源的 Shroom 记录，不成为绕过权限的在线回退。旧系统、Wiki、Outline 和 OpenClaw 文件仍只允许作为一次性迁移输入。

| 数据 | 运行时位置 |
|---|---|
| 账户、会话、日记、数据源连接、外部活动、未解之问、菇卡、待办、人脉、观察席、AI 派生结果、AI 用量与扣费账本、菇点余额、充值订单、活动奖励、功能解锁、协议接受、退款申请、人生 OS、复利推进 | Shroom PostgreSQL |
| Codex 任务列表 | 用户电脑上的 Codex app-server；菇只接收最小任务事实 |
| 日记图片对象 | 私有腾讯 COS 桶 `shroom-1303825367` |
| 语音对象 | 当前为 Shroom 服务器私有本地存储 |
| 图片/语音所有权与对象键 | Shroom PostgreSQL `media_assets` |
| 语音转写、观察席分析、人生 OS 整理、复利推进辅助 | 外部处理器；不是业务存储 |

所有私有业务行都归属 `user_id`。媒体通过短时授权链接读取，COS 凭据不下发客户端。只有 `ai_allowed = true` 的日记可以进入记忆检索或 AI 整理上下文；只有连接上 `ai_allowed = true` 的外部活动，才可在用户主动发起当天日记分析、主动打开每日总结，或开启 22:00 收件箱/邮件投递时作为来源上下文；`include_in_diary` 只控制时间线展示，两个选项互不绑定。

## 7. AI 产品规则

1. **先回答用户真正的问题**：模型负责理解问题，检索和统计只是给模型准备可靠证据，不能为每个问法制造一个关键词特例。
2. **区分事实、解释和假设**：日期、数量和原文是事实；情绪、模式和价值倾向是解释；证据不足时必须表达不确定。
3. **提供依据和反例**：长期结论不能只展示支持材料，还要允许冲突经历使结论降级为“待观察”。
4. **不自动升级**：一段日记不会自动变成菇卡或完成复利推进，菇卡不会自动变成人生 OS，人生 OS 不会自动变成待办；复利结果也必须由用户确认。
5. **不越过心理健康边界**：不做医学诊断、不暗示危机已经被专业处理；出现明显风险时应建议现实支持或专业帮助。

## 8. 跨平台体验原则

Shroom 使用 uni-app 保持 H5、iOS、Android 和小程序的共同业务层，但不假设各端交互完全相同。

- 主要内容宽度、底部安全区、状态栏和软键盘遮挡必须分别处理。
- 表单、录音、文件选择、返回行为和权限提示使用 uni-app 能力与条件编译，不依赖 H5 私有 DOM。
- 长任务必须显示阶段、已用时间或可解释的进度，不用只有旋转图标的未知等待。
- 所有输入和转写结果必须自动换行、限制容器宽度，并在小屏不产生横向溢出。
- 页面首次进入就加载完整首屏状态，不能要求用户额外点击才能触发日历标记或已有内容。
- 视觉应保持安静、温暖、编辑感和足够留白，避免通用后台卡片墙和与日记主题割裂的组件皮肤。

## 9. 产品边界与非目标

- 不恢复或兼容冲浪家商城、课程、学校、分销等业务代码或数据；Shroom 只保留自身菇点充值、数字功能解锁与 AI 用量结算。
- 不把 Shroom 做成公开日记社区；公开对象是用户挑选的菇卡。
- 不把 AI 生成内容伪装成用户已经认可的自我描述。
- 不追求无限增加人生 OS、标签、分析报告或每日 AI 任务。
- 不以活跃时长或 AI 调用次数作为首要成功指标。

Shroom 与 EvoX、ExtremeNomad、灵魂冒险属于同一位创作者的项目组合，但当前产品、账户和数据边界保持独立。未来若建立共同身份或数据协作，必须另行定义授权和用户可见的产品价值，不能因为同属一个项目组合而默认互通。

## 10. 当前验证指标

近期产品验证应关注：

- 用户能否稳定记录，且历史日记和媒体不丢失。
- 用户提出自然语言问题后，回答是否覆盖正确时间范围、引用正确日记并允许纠错。
- 用户是否愿意保留、再次使用或主动公开一张菇卡。
- 人生 OS 整理是否实际减少重复，而非产生更多文字；用户能否解释每条为什么保留。
- 复利系统是否让用户清楚地为少数长期投资分配时间、设定取舍，并用真实进度与结果证据修正计划。
- AI 建议被接受、修改、拒绝的比例，以及拒绝原因，而不是只统计生成次数。
- H5、App 和小程序在核心记录、回看、确认流程上的任务完成率与错误率。

## 11. 已知后续决策

以下是候选方向，不是已实现承诺：

- 语音从服务器本地存储迁移到独立私有 COS 路径。
- 在不增加一级页面的前提下，持续积累“模式候选”，只在证据成熟或复查时展示。
- 为人生 OS 增加按条恢复、更加细致的来源查看和长期触发效果评估。
- 把“行动”从普通待办进一步发展为有假设、结果和复盘的轻量实验；必须先验证真实需求。
