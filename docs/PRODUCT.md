# Shroom 产品定义

> 状态：当前产品基线
>
> 更新：2026-09-11
>
> 适用：产品设计、前后端实现、AI 提示词、数据迁移与验收

## 1. 产品是什么

Shroom 是一款以私人日记为原点的 AI 记忆、理解与轻社交产品。它帮助用户保存真实经历，在需要时找回和讨论过去，从经历中形成可复用的理解，并逐步澄清自己认可的判断标准。

它不是通用笔记、内容社区、心理诊断工具，也不是把每段日记自动加工成建议的 AI 流水线。

产品核心链路是：

```text
记录经历 → 找回与讨论 → 形成理解 → 校准判断标准 → 用户决定是否行动或分享
   日记         回看          菇卡          人生 OS             待办 / 发现
```

AI 在这条链路中负责检索、比较、提出假设和解释依据；用户始终拥有原始经历、最终含义、是否采纳以及是否公开的决定权。

## 2. 产品承诺

Shroom 应长期保护以下四件事：

1. **经历不被改写**：日记是用户当时经验的原始记录，AI 结果只能作为派生内容存在。
2. **理解可以追溯**：重要结论应能回到具体日记或用户自己的菇卡，不用空泛的人格标签代替证据。
3. **用户拥有解释权**：AI 可以提出候选理解，不能替用户定义身份、价值观或人生方向。
4. **私密默认、公开明确**：日记、媒体、人生 OS 和新菇卡默认私密；只有用户明确选择的菇卡进入发现。

## 3. 核心对象与边界

| 对象 | 它回答的问题 | 产品定义 | 它不是什么 |
|---|---|---|---|
| 日记 | 当时发生了什么？ | 对经历、感受与想法的原始记录 | AI 结论或公开动态 |
| 回看对话 | 我的过去与此刻有什么关系？ | 基于本人日记、带来源引用的搜索和讨论 | 只靠标签或关键词匹配的搜索框 |
| 未解之问 | 哪些问题需要时间和新经历才能理解？ | 跨日记积累用户确认的证据，并保存可修订的阶段理解 | 日记分类、待办或一次性 AI 问答 |
| 观察席分析 | 这一次还可以怎样理解？ | 针对本次日记、由用户选择角度的多席观察 | 心理诊断或唯一答案 |
| 菇卡 | 下次遇到相似时刻，我想带着什么理解？ | 可复用的理解、提醒或观察视角 | 行动、待办、承诺或人生原则仓库 |
| 人生 OS | 对我而言，什么才叫“更好”？ | 少量、当前生效、由用户签发的判断标准、边界和复盘问题 | 性格报告、AI 定义的身份或无限增长的语录集 |
| 待办 / 实验 | 接下来具体做什么？ | 有明确行动含义、可以完成的用户承诺 | 菇卡或人生 OS |
| 人脉 | 我怎样理解并维护一段关系？ | 私人的关系档案、互动、里程碑与提醒 | 通讯录复制品或公开社交关系图 |
| 发现 | 哪些他人的理解值得共鸣？ | 只展示用户明确公开的菇卡 | 日记广场或泛内容信息流 |

最重要的区分是：

> 菇卡帮助我在具体时刻做得更好。
>
> 人生 OS 帮助我决定什么才叫“更好”。

菇卡中可以包含“如何使用这份理解”的提示，也可以记录后来怎样实践，但这不改变菇卡的本体：它仍然是一份理解，而不是行动对象。真正需要执行、截止或完成状态的内容进入待办/实验系统。

## 4. 信息架构

一级导航固定为：

- **日记**：写日记、日历、按日回看、归档、搜索与 AI 记忆讨论。
- **菇卡**：管理自己的可复用理解与使用记录。
- **发现**：浏览、共鸣、收藏和复制被明确公开的菇卡。
- **我的**：账户、年度记录反馈、待办、人脉、关系提醒、人生 OS 与数据导出。

模式候选层不是一级页面。AI 对“似乎反复出现”的判断应以“待观察”存在于回看或人生 OS 整理流程中，带支持证据、反例和不确定性；没有足够价值时不需要单独产品化。

未解之问也不增加一级页面：日记首页只展示当前问题入口，完整管理放在「我的」，写日记时提供可选关联。它不制造「困惑日记」分类，也不依赖标签筛选。

行动层由待办/实验承载，也不侵入菇卡和人生 OS 的定义。

## 5. 当前产品能力

以下是截至 2026-09-09 已进入代码或生产环境的能力。

### 5.1 账户与会话

- 手机号和密码注册、登录。
- 短期访问令牌配合可轮换刷新令牌，前端协调并发刷新。
- 每个请求从登录会话或受限 API Token 确认用户身份，不接受客户端传入 `userId` 选择数据。
- 短信登录、短信找回和第三方登录尚未启用。

### 5.2 日记与媒体

- 支持日期、可选具体时间或全日记录、心情、图片、语音和隐私状态；不要求用户手工给私密日记分类。
- 日历首次打开即加载当月记录；归档使用分页加载，避免一次拉取全部历史数据。
- 历史日记未配置时间时保持为全日记录，不伪造 23:00。
- 语音先私密保存，再由用户主动发起高精度转写；转写结果可编辑，只有用户点击加入正文并保存后才成为日记内容。
- 图片在服务端校正方向、移除 EXIF/GPS，并按内容选择无损或高质量 WebP；处理后的文件不得大于原文件，否则保留更小且安全的版本。

### 5.3 回看与日记记忆

- 支持从顶部进入对本人日记的搜索与讨论，也支持写完日记后发起“与这次经历相关的过去”讨论。
- 检索不是只看心情标签或关键词：系统使用文本检索、向量召回、模型语义判断和原文引用回答跨日记问题。
- 回答保存来源清单和引用；用户可以标记“不是同一件事”“理解错了”“现在不想谈”或“有帮助”。
- 日记正文改变时，派生索引和旧分析按版本失效，不覆盖原始日记。
- 归档中的“成长 / 情绪 / 关系 / 工作 / 旅行 / 灵感”是稳定的语义回看口径，不是日记标签。首次打开盘点正文，之后仅增量分析新增或修改的日记。

### 5.4 AI 分析、菇卡与行动

- 每个新用户默认拥有第一性原理、熵增/熵减、人生复利、人生 OS 对照与生物驱动五个观察席；用户可以暂停默认席位，并创建、编辑、启停或删除自己的观察席。
- 每次观察开始时固化当时启用的席位快照，后续修改个人设置不会改写历史分析；自定义席位与默认席位共享“只依据正文、区分事实与解释、不替用户下结论”的边界。
- 观察席分析由已配置的 AI 服务生成，结果与原日记分开存储。启用席位越多，单次分析的模型调用与成本通常越高。
- 每次日记观察和每次回看都记录供应商返回的输入、缓存命中/未命中、输出及总 token，并保存调用发生时的公开价格快照。DeepSeek 页面直接展示易懂的人民币预计花费；优惠额度、税费和供应商最终扣费不伪装为产品可确认的精确账单。
- 上线记账前发生的历史 AI 调用没有 usage 记录，不做虚假的费用回填。
- AI 可以建议创建私密菇卡、绑定已有菇卡或创建待办，但三者都需要用户明确确认。
- 保存日记不会自动生成菇卡；分析完成后只提示可选动作。
- 菇卡支持私密、匿名公开、实名公开、共鸣、收藏、复制和后续使用记录。
- 从他人的公开菇卡复制时，创建属于当前用户的新副本，不共享私密所有权。

### 5.5 未解之问

- 用户可以保存暂时无法靠一次讨论回答的长期问题，并补充背景。
- 日记只有在用户写作时明确选择后才成为问题线索；一篇日记最多关联三个问题，不静默抓取浏览器历史或外部数据。
- 问题积累至少两条允许 AI 读取的线索后，用户可以主动复盘。AI 同时整理支持、反例、变化、未知项和下一次值得观察的内容。
- 新增三条线索，或已有新线索且上次复盘超过 14 天时，产品只提示「适合再看看」，不会自动消费 API 或覆盖结论。
- 每次复盘形成不可变版本并计入独立 token/人民币费用账本；问题是否继续、暂停或已经想明白只能由用户确认。
- 详细机制见 [INQUIRIES.md](./INQUIRIES.md)。

#### 发现广场与公开菇卡

- 发现广场和个人菇卡的卡片浏览统一使用单张左右翻阅；纵向滚动留给页面信息和完整详情。个人菇卡仍是自己的理解库，详情承担编辑、练习和引用到日记，不把社交热度变成个人库的排序标准。
- 点开公开菇卡后，访客只能看到作者主动公开的觉察句、个人理解、使用提示、标签、选择的署名方式，以及共鸣、收藏、引用等聚合计数。
- 原始日记、日记来源 ID、AI 分析来源、私人练习内容和个人练习次数不属于公开卡片，不能因为菇卡公开而被带到广场。
- **共鸣**表示“这份理解也击中了我”，是可取消的轻量公开反馈，不产生菇卡所有权，也不能对自己的卡共鸣。
- **收藏**是当前用户的私密书签，可以取消；收藏不会复制内容，也不会让原作者看到收藏者的私人记录。
- **引用到我的菇卡**会保存一个属于当前用户的私密快照，并以 `copiedFromId` 保留来源。重复引用同一公开卡返回已有副本，不制造重复卡。

#### 人物档案与普通用户使用同一种菇卡

- 菇卡不因来源不同而拆成两种产品类型。「人类留给自己的提醒」中的卡片就是人物模拟用户公开的普通菇卡，使用相同的卡片结构、浏览方式、共鸣、收藏、引用和练习链路。
- 历史人物是日记、手稿等材料的来源；现代觉察句、解释和使用提示由 Shroom 转译形成。人物姓名可以作为档案昵称，但来源详情必须说明这是 Shroom 建立的只读人物档案、并非本人注册或逐字发布。
- 每位历史人物使用一个不可登录的只读用户档案，名字使用真实姓名；相关菇卡通过正常 `user_id` 归属该档案，与普通用户卡共用 `users`、`cards` 和全部社交关系表。
- 详情仍保留作品、位置与 Shroom 转译说明，用于区分“卡片归属人物”与“文字是历史原句”这两个不同事实。
- 人物集合只保留为内部来源与运营元数据，不在发现页生成独立专题卡或第二套入口；人物菇卡直接与其他用户公开菇卡共同展示。
- **练习别人的卡**必须先产生自己的私密副本；后续修改、练习记录和日记关联全部写在自己的数据空间，不改写原作者的卡。
- 被引用后的个人副本可以直接带入新日记。这里的“引用”是有来源的个人化复用，不是把别人的卡或日记共同编辑。

### 5.6 人生 OS

- 人生 OS 已升级为按条原则管理：每条包含领域、判断标准、适用边界、复盘问题、形成方式、置信状态、支持依据和反例。
- AI 整理只生成待确认提案，不直接改写当前版本。
- 用户可以逐条编辑、排除、合并采纳，并明确选择是否把具体情境理解另存为私密菇卡。
- 签发后生成新版本，旧版与来源引用保留；当前生效原则建议 5–9 条，当前硬上限 50 条。
- 详细机制见 [LIFE_OS.md](./LIFE_OS.md)。

### 5.7 人脉与关系维护

- 每个用户拥有隔离的关系档案、互动记录、评分历史、关系待办、里程碑和提醒设置。
- 保存或修改已授权 AI 的日记后，后台从正文证据整理具体人物与互动事件。模型只能提出已允许的评分规则代码，实际加减分由程序确定，不采信模型自报分值。
- 人脉整理按日记版本幂等；重试不会反复加分，编辑、删除或撤回 AI 授权时会回滚原版本自动写入的事件、评分和承诺待办。
- 月度关系回顾与提醒属于用户的私人辅助，不进入发现广场，也不自动影响人生 OS。

### 5.8 数据导出与个人 Agent

- 用户可以导出自己的日记、菇卡、关系、待办、分析、人生 OS、人生 OS 原则和整理提案。
- Shroom 龙虾/个人 Agent 使用独立、可撤销、仅保存摘要且按资源授权的 API Token；不能使用账户密码或浏览器刷新令牌代替。

### 5.9 Owner 复利系统

- 「我的」可为指定 owner 展示一个私有「复利系统」，把系统、金融、信用、身体分别作为每日、每月、随承诺发生和每日的长期账户，而不是合并成一张通用打卡表。
- 系统复利从脱敏 Codex 统计自动判断，信用复利从该用户的人脉承诺自动聚合；用户只为无法自动证明的身体跟练、晨间祷告和月度金融规则执行做确认。
- 晨间祷告未录入固定原文前不启用、不计入完成率；金融记录只确认是否按规则执行，不记录或评价短期收益。
- 第一版严格按配置的用户 UUID 双重隔离入口与接口，不因知道手机号或页面地址而获得访问权。详见 [COMPOUND_SYSTEM.md](./COMPOUND_SYSTEM.md)。

## 6. 数据与隐私边界

Shroom 只有一个运行时业务数据源：独立 PostgreSQL 数据库。旧系统、Wiki、Outline 和 OpenClaw 文件只允许作为一次性迁移输入，迁移完成后不能成为在线回退数据源。

| 数据 | 运行时位置 |
|---|---|
| 账户、会话、日记、未解之问、菇卡、待办、人脉、观察席、AI 派生结果、AI 用量账本、人生 OS | Shroom PostgreSQL |
| 日记图片对象 | 私有腾讯 COS 桶 `shroom-1303825367` |
| 语音对象 | 当前为 Shroom 服务器私有本地存储 |
| 图片/语音所有权与对象键 | Shroom PostgreSQL `media_assets` |
| 语音转写、观察席分析、人生 OS 整理 | 外部处理器；不是业务存储 |

所有私有业务行都归属 `user_id`。媒体通过短时授权链接读取，COS 凭据不下发客户端。只有 `ai_allowed = true` 的日记可以进入记忆检索或 AI 整理上下文。

## 7. AI 产品规则

1. **先回答用户真正的问题**：模型负责理解问题，检索和统计只是给模型准备可靠证据，不能为每个问法制造一个关键词特例。
2. **区分事实、解释和假设**：日期、数量和原文是事实；情绪、模式和价值倾向是解释；证据不足时必须表达不确定。
3. **提供依据和反例**：长期结论不能只展示支持材料，还要允许冲突经历使结论降级为“待观察”。
4. **不自动升级**：一段日记不会自动变成菇卡，菇卡不会自动变成人生 OS，人生 OS 不会自动变成待办。
5. **不越过心理健康边界**：不做医学诊断、不暗示危机已经被专业处理；出现明显风险时应建议现实支持或专业帮助。

## 8. 跨平台体验原则

Shroom 使用 uni-app 保持 H5、iOS、Android 和小程序的共同业务层，但不假设各端交互完全相同。

- 主要内容宽度、底部安全区、状态栏和软键盘遮挡必须分别处理。
- 表单、录音、文件选择、返回行为和权限提示使用 uni-app 能力与条件编译，不依赖 H5 私有 DOM。
- 长任务必须显示阶段、已用时间或可解释的进度，不用只有旋转图标的未知等待。
- 所有输入和转写结果必须自动换行、限制容器宽度，并在小屏不产生横向溢出。
- 页面首次进入就加载完整首屏状态，不能要求用户额外点击才能触发日历标记或已有内容。
- 视觉应保持安静、温暖、编辑感和足够留白，避免通用后台卡片墙和与日记主题割裂的组件皮肤。

## 9. 产品边界与非目标

- 不恢复或兼容冲浪家商城、课程、学校、支付、分销等业务代码或数据。
- 不把 Shroom 做成公开日记社区；公开对象是用户挑选的菇卡。
- 不把 AI 生成内容伪装成用户已经认可的自我描述。
- 不追求无限增加人生 OS、标签、分析报告或每日 AI 任务。
- 不以活跃时长或 AI 调用次数作为首要成功指标。

Shroom 与 EvoX、ExtremeNomad、灵魂冒险属于同一位创作者的项目组合，但当前产品、账户和数据边界保持独立。未来若建立共同身份或数据协作，必须另行定义授权和用户可见的产品价值，不能因为同属一个项目组合而默认互通。

## 10. 当前验证指标

近期产品验证应关注：

- 用户能否稳定记录，且历史日记和媒体不丢失。
- 用户提出自然语言问题后，回答是否覆盖正确时间范围、引用正确日记并允许纠错。
- 用户是否愿意保留、再次使用或主动公开一张菇卡。
- 人生 OS 整理是否实际减少重复，而非产生更多文字；用户能否解释每条为什么保留。
- AI 建议被接受、修改、拒绝的比例，以及拒绝原因，而不是只统计生成次数。
- H5、App 和小程序在核心记录、回看、确认流程上的任务完成率与错误率。

## 11. 已知后续决策

以下是候选方向，不是已实现承诺：

- 语音从服务器本地存储迁移到独立私有 COS 路径。
- 在不增加一级页面的前提下，持续积累“模式候选”，只在证据成熟或复查时展示。
- 为人生 OS 增加按条恢复、更加细致的来源查看和长期触发效果评估。
- 把“行动”从普通待办进一步发展为有假设、结果和复盘的轻量实验；必须先验证真实需求。
