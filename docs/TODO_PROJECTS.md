# 待办与项目行动层

## 定位

待办回答“具体要做什么”，项目回答“这些行动共同要做成什么”，复利计划回答“接下来的时间投向哪里，会长期积累什么”。三者分开存储；任务可以没有项目，也可以不关联复利计划。

待办是 Shroom 唯一的行动执行层。复利系统和日记 AI 只能预填或建议这套待办，不建立第二份列表，也不能替用户宣告任务完成。

## 用户路径

- “我的 → 待办”进入统一首页。页内有当前、之后、未安排和项目四个视图；全部待办、已完成、批量整理和导出在页面菜单。
- 新建时只要标题，默认无日期、无项目、无复利方向。安排日期和真正的截止日期分开。
- 无日期任务也能“开始推进”，并在跨天后保留进行中状态。只有超过真实截止日期才显示“已过截止日期”；过去的安排日期只显示为“之前安排”。
- 完成可以留下结果，并在完成当天生成独立系统行动记录。它不是用户的第一人称日记；撤销完成时会将对应行动记录标记失效。
- 项目内按进行中、待做、已完成、已取消分组。手机用菜单调整顺序，H5 桌面可直接拖动同组任务。

## 重复任务

数据上使用 `todo_recurrence_rules` 规则和带 `recurrence_rule_id + occurrence_date` 的独立 `todos` 实例。每天、每周和每月规则按用户时区在打开页面时向前生成有限窗口，唯一索引保证多次打开或网络重试不会生成重复实例。

每个实例有自己的状态、结果和完成时间。每月 31 日在短月使用月末，下月恢复 31 日。编辑时必须选择“仅本次”或“本次及以后”，后者只替换未完成的当前/未来实例，已完成记录保留。“跳过本次”记录为跳过，不冒充完成。

## 数据与可靠性

| 实体 | 表 | 关键边界 |
|---|---|---|
| Task / TaskOccurrence | `todos` | 同一 ID 可在多视图出现；状态、日期、项目和复利方向分开存储 |
| Project | `todo_projects` | 完成不代替任务完成；归档未完成任务时必须选择保留、转移或取消 |
| RecurrenceRule | `todo_recurrence_rules` | 规则和实例分离，过去的结果不被重置 |
| TaskEvent | `todo_events` | 保留状态变化、来源引用和可撤销的系统行动记录 |

创建、完成和规则更新都支持请求幂等标识；任务与项目更新使用 `version` 检查多窗口冲突。所有查询以登录会话中的 `user_id` 隔离，不接受客户端传入用户 ID。

## 迁移、API 与导出

- 按顺序执行 `server/sql/026_todo_projects.sql`。该迁移只为旧 `todos` 增加可选列，不改写旧文字、日期和完成状态。
- 现行 API 位于 `/api/todos/v1/*`，实现见 `server/src/routes/todos.js`。核心入口是 `GET /home`、`POST /create`、`PATCH /status`、`/projects/*` 和 `/recurrences/*`。
- `GET /api/todos/v1/export?format=json|markdown` 导出待办、项目、重复规则、结果和关联标识，不默认带出无关日记全文。全量个人数据导出也包含这些表。

## 已知边界

- 首版不承诺后台推送；重复实例在用户打开待办相关页面时检查和生成。
- 完成结果可关联最多 9 张照片，复用日记的私密媒体上传、压缩和短时签名访问流程。首版尚未支持通用文档附件。
- 日记 AI 可建议创建待办，且保留日记来源；“关联已有待办/建议更新完成”尚未开放交互，AI 仍不会自动修改任务状态。
