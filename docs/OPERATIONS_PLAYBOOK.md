# Shroom 运营与获客部门工作手册

> 状态：v1，进入真实运营前的执行基线  
> 更新：2026-09-18  
> 产品定位：AI 人生数据库  
> 核心承诺：让过去的经历在未来真正帮到你

## 1. 部门为什么存在

增长与复利部门负责设计和验证增长机制；运营与获客部门负责把已经能够演示的产品价值带到真实市场，获得可归因的新用户和反馈。两个部门不能互相冒充：产品代码、内容草稿和曝光量都不是获客结果。

首批目标用户不是泛化的“想成长的人”，也不以职业身份划分。第一目标客群是：已经在日记、备忘录、语音或文档里积累过一批记录，却很少回看；相似的关系、工作或自我问题再次出现时，仍然从零回忆、从零判断的人。他们的共同问题不是缺少记录工具，而是“写了很多，却没有用起来”。

## 2. 顶级运营方法在 Shroom 的翻译

1. **以受众问题开始。** 选题必须来自公开搜索、真实评论、产品反馈或已授权访谈，不能由模型凭空想象。
2. **以产品证据建立差异。** 每条内容至少包含产品录屏、真实过程、可核验功能或明确来源之一；不做泛 AI 自我成长鸡汤。
3. **平台原生，而非机械分发。** 同一核心事实可以复用，但开头、节奏、视觉、长度和互动动作必须为平台重做。
4. **系列化积累。** 用重复栏目积累用户预期，按 28 至 90 天观察模式，不被一次爆款绑架。
5. **测量完整漏斗。** 内容判断依次看吸引、消费、满意、有效到访、首次价值激活、七日回访和真实对话。
6. **AI 负责增效，人负责公开。** Agent 可以研究、起草、改编和复盘；事实门禁与 CEO 决定是否发布。第一阶段不自动发帖。
7. **用可信说服，不用操纵。** 固定使用“身份识别 → 具体痛点 → 原因机制 → 可核验证据 → 用户控制 → 低摩擦行动”；没有真实证据时，不用虚假社会认同、权威、稀缺或紧迫感补齐。

这些原则综合了平台当前的公开指导：YouTube 建议按内容栏目分组并观察较长窗口，而不是用单条爆款指导下一条；其推荐分析把表现拆为吸引、参与和满意。TikTok 的官方创意框架强调平台原生、开头—主体—收束和持续测试多种创意。Bilibili 与中国现行规则都要求真实性、版权和 AI 生成内容标识。参考：[YouTube 内容策略](https://support.google.com/youtube/answer/13616340)、[YouTube 推荐表现](https://support.google.com/youtube/answer/16559650)、[TikTok Creative Codes](https://ads.tiktok.com/business/en/creative-codes)、[Bilibili 社区公约](https://member.bilibili.com/studio/convention/)、[人工智能生成合成内容标识办法](https://www.cac.gov.cn/2025-03/14/c_1743654685899683.htm)。

## 3. 首月渠道选择

不同时铺满所有平台。

- **小红书是首要发现入口**：每周最多 3 个原生图文或短视频实验，先验证目标客群与痛点语言。自然内容不放站外链接、二维码或联系方式，也不以暗语诱导私信、主页跳转和互动。
- **微信视频号建立创始人信任**：每周 2 条原生短视频，讲真实经历、产品为什么存在和一次具体用法。
- **公众号承载深度内容母稿**：每周 1 篇，把方法、案例与版本进展沉淀为长期可查内容。
- **官网、GitHub、公众号菜单和小程序承接转化**：只有这些合规承接入口或平台批准的商业产品使用注册链接与归因编号。
- **抖音暂作第二阶段实验**：只有当一个短视频栏目在视频号得到初步验证，才重新制作抖音原生版本。

发布量是获得学习样本的节奏，不是绩效目标。任何栏目连续四周没有目标用户信号，应调整或停止。

平台是否分发由平台决定，任何内容都不能保证“不限流”。运营目标是降低风险：不做站外导流、标题党、虚假互动、医疗承诺、低质截图和伪装广告；内容本身先解决一个小问题，产品只作为真实机制与证据出现。

## 4. 三个首发栏目

账号架构采用一个 Shroom 品牌官方主号承载三个栏目，不按身心记录、人生 OS、菇卡、未解之问等产品功能拆分专题账号。功能面对的是同一目标用户和同一价值链，拆号会分散信任、内容供给与验证样本。未来只有在主号完成至少 12 周、36 篇原创内容，某一方向形成独立受众、独立产品承接和连续 8 周供给能力后，才提交 CEO 决定是否拆分。第二账号优先考虑真实创始人个人号，而不是功能矩阵号。完整门槛见 [`XIAOHONGSHU_DEEP_RESEARCH_AND_ACCOUNT_STRATEGY.md`](./XIAOHONGSHU_DEEP_RESEARCH_AND_ACCOUNT_STRATEGY.md)。

### 问问过去的自己

用一个真实问题展示 Shroom 如何找到历史证据、区分事实与推断，并给出可检查的回答。内容重点是“过去的信息今天产生了什么帮助”。

### 日记如何变成人生数据库

每次只演示一个闭环，例如日记到未解之问、身心记录、人生 OS 或相关过去回看。避免功能清单式广告。

### 创始人真实开发日志

公开一个真实产品判断、失败、修正和验证结果。它不是成功人设包装，而是让目标用户理解产品为何如此设计。

### 热点如何进入三个栏目

热点不是第四个栏目。小红书一方热点、Shroom 自有反馈、品类重复问题、跨平台信号和可预期生活节点先进入热点雷达；只有来源、时效、目标用户相关性、Shroom 独有判断和安全边界全部成立，才路由进上述三个栏目。跨平台信号必须明确标注，不能伪装成小红书站内热点；超过截止时间后转成常青题或放弃。

## 5. 90 天运营计划

### 0—30 天：定位与内容证明

- 建立三个栏目和平台原生模板；
- 每条内容分配唯一内容编号和对应落地场景；
- 建立小红书、视频号、公众号的零基线；
- 找到至少两类能够持续产生目标用户收藏、具体问题或有效到访的内容。

### 31—60 天：首次价值激活证明

- 保留最有证据的两个栏目；
- 每条内容只进入一个具体产品场景，不丢到无差别首页；
- 观察用户是否完成首篇日记、首次 AI 回看，并愿意提供真实反馈；
- 把评论和私信中的高频问题反馈给产品，而不是只做销售话术。

### 61—90 天：传播复利证明

- 在用户逐项授权后发布真实使用案例；
- 测试创作者合作、邀请和公开表达回流；
- 只有自然内容已产生稳定激活，才向 CEO 申请小额付费放大；
- 付费只放大已验证内容，不用投放掩盖产品价值不足。

## 6. Agent 工作流

```text
公开信号与产品反馈
  → 用户洞察与选题 Agent：问题地图
  → 运营总管：单一内容简报
  → 小红书标杆与目标用户信号分析 Agent：今年持续账号、可迁移机制、变量、证据标准与停止条件
  → 小红书热点雷达 Agent（可选）：来源、有效期、硬停止、六维评分和栏目路由
  → 内容主编与制作 Agent：证据与母稿
  → 小红书内容生成 Agent：平台原生候选稿与素材清单
  → 内容事实与合规 Agent：PASS / STOP
  → CEO：批准 / 修改 / 拒绝
  → 新媒体运营 Agent：只发布已批准版本并记录
  → 社群与转化 Agent：回应和场景承接
  → 数据归因与复盘 Agent：周度保留 / 调整 / 停止
```

小红书标杆与目标用户信号分析 Agent、热点雷达 Agent 与内容生成 Agent 必须分离：研究者不能写最终稿或批准发布，生成者不能给自己的内容打分。标杆研究必须把“账号持续增长”和“单篇爆文”分开，热点必须把小红书一方信号与跨平台信号分开，只有可追溯证据才能进入结论。完整责任卡见 [`XIAOHONGSHU_AGENT_SYSTEM.md`](./XIAOHONGSHU_AGENT_SYSTEM.md)。

每份内容简报固定回答：面向哪一类具体人、发生在什么具体时刻、最疼的一件事是什么、为什么会发生、展示什么真实证据、发布到哪里、该平台允许用户完成什么单一动作、如何归因、什么结果意味着停止。目标客群、痛点和行动不一致时不得进入制作。

## 7. 核心指标

| 指标 | 定义 |
|---|---|
| 目标用户内容信号 | 目标人群的收藏、具体问题、案例反馈或主动转发 |
| 有效到访 | 通过唯一内容编号进入对应 Shroom 场景的去重访客 |
| 首次价值激活 | 新用户完成首篇日记并获得一次可理解的 AI 回看 |
| 七日价值回访 | 激活用户七日内再次记录、回看或询问过去的自己 |
| 真实对话 | 用户明确描述长期记录问题、使用反馈或合作意向 |

曝光、粉丝、稿件数量和 AI 生成次数是诊断量，不是最终结果。

## 8. 公开门禁

- 不使用未授权的私密日记、健康记录、人脉、财务或位置资料；
- 用户案例逐项授权，撤回后停止后续使用；
- AI 参与生成或合成的内容按法律和平台要求显式标识；
- 涉及健康和心理只说明产品观察边界，不冒充医疗专业人士；
- 不伪造创始人经历、用户反馈、使用人数和效果；
- 未经 CEO 明确批准，不自动发布、购买投放、联系达人或代表品牌承诺。
