# Shroom 日记回看架构

## 边界

该能力只使用 Shroom PostgreSQL 中当前登录用户的日记、回看会话和菇卡，
不读取旧 Wiki、冲浪家业务库或 EvoX。客户端和模型都不能传入任意 user_id；
用户身份始终由登录会话或具备 memory:* 范围的专用 API Token 在服务端注入。

## 数据流

1. 新增日记时，原文与 diary_index_tasks 在同一事务提交；保存不等待模型。
2. 正文或语音转写修改会递增 content_version 和 index_epoch，立即清理旧片段并使引用旧版本
   的回答失效。心情、媒体或记录时间不参与正文语义归类。
3. 关闭 ai_allowed 或软删除日记会在同一事务取消任务、删除片段、清空受影响回答
   的派生内容并递增用户 corpus_revision。
4. 索引 Worker 使用 FOR UPDATE SKIP LOCKED 领取五分钟租约。Embedding 请求在
   数据库事务之外执行；发布前再次锁定日记并核对用户、版本、epoch、删除状态和
   AI 权限。完整片段一次性发布，旧任务不能覆盖新正文。
5. 回看 Worker 同样使用持久化任务、租约、退避和重试。每个自然语言问题先由
   Question Planner 生成受约束的分析计划，明确 intent、criterion、时间范围、
   统计单位、分组方式、匹配口径和执行策略。用户手选范围始终是不可突破的硬边界，
   模型给出的未来日期也会被执行器截断到当前日期。
6. 质性问题执行语义、正文关键词和时间分层检索，再把有限原文片段交给主模型；
   数量、完整日期和分布问题执行 semantic census，逐篇读取范围内全部授权正文，
   由模型判断任意语义 criterion，由程序确定性去重、分组和计算。未完整读取时不得
   发表精确统计；mood 不能代替正文证据。固定主题首次对授权日记做语义盘点，
   之后复用逐篇版本缓存，只核对新增或修改的正文。
7. 模型只引用后端生成的 S1…Sn。入库前重新读取权威日记，逐项校验用户归属、
   权限、正文版本、UTF-16 起止位置和 slice 原文；无有效来源的实质性观察被丢弃。
8. 用户纠正按“不是同一事件 / 解释不对 / 暂不讨论 / 有帮助”分别保存并进入后续
   对话上下文，但不改写原日记。菇卡只在用户明确确认后创建，记录会话、消息和
   每篇来源日记的版本。

## 偏移与切片

source_start/source_end 使用 JavaScript 与前端一致的 UTF-16 code unit、左闭右开
区间。切片优先保持短日记和自然段完整，超长段落在标点或空白处拆分，且不会切开
Emoji 的 surrogate pair。chunker_version、预处理版本与 Embedding 模型、维度
一起组成 embedding_profile_id。

## 检索降级与回填

EMBEDDING_* 未完整配置时，日记仍能正常保存，索引任务保留等待配置；回看使用
真实的正文关键词与时间分层样本，响应中明确 semanticIndexEnabled=false 和
实际覆盖。不会生成假向量或把关键词相似度宣称为语义相似。

配置新的 Embedding profile 后，旧向量空间不会参与查询，Worker 自动创建回填
任务；也可运行：

    npm run backfill:memory

## 部署

1. 安装与 PostgreSQL 主版本匹配的 pgvector 包，并由数据库管理员确保
   `vector`、`pg_trgm` 扩展可用。
2. 使用 Shroom 服务的专用数据库角色依次执行 sql/010_diary_reflection.sql 至
   sql/013_remove_affect_specific_cache.sql。若迁移
   必须由管理员执行，完成后要把新增表、序列和函数的所有权或最小权限显式授予
   Shroom 服务角色，不能让应用依赖超级用户连接。
3. 在服务端环境文件配置主模型；如要启用语义检索，再配置完整 EMBEDDING_*，
   维度必须与接口实际响应一致。
4. 部署服务代码和 H5 静态文件，重启 shroom-api.service。
5. 检查 /api/health 与登录后的 /api/memory/v1/status，再用真实账号验证
   “保存 → 任务 → 回看 → 原文 → 纠正 → 追问 → 确认菇卡”。

普通日志只记录任务 ID、错误码和脱敏供应商状态，不记录日记正文、模型输入或密钥。

## 回滚与清理

前端入口可先回滚，数据库新增列和表保持兼容。紧急停用后台处理时设置
MEMORY_WORKER_ENABLED=false 并重启；日记保存仍可用，任务留在数据库等待恢复。
停用语义供应商时移除 EMBEDDING_*，系统自动降级为关键词与时间检索。

不要直接删除仍在引用中的表。需要永久移除功能时，先导出用户确认保存的菇卡来源，
停止 Worker，删除回看路由与入口，再按反向外键顺序删除派生表；权威 diaries
原文不随功能回滚删除。
